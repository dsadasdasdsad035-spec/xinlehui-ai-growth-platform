## 0. 现状与已核查的缺口

### 0.1 一个必须优先修的正确性问题：作品与学员的对应关系是「猜」的

`prototype/src/main.jsx:675` 的 `ClassMediaMosaic` 用**数组下标取模**生成展签：

```js
`${students[index % students.length]} · 《${titles[index % titles.length]}》 · 2026.08.11`
```

后果：

- 给 18 人班批量上传 3 幅作品，展签会循环显示「陈一诺 / 林小满 / 赵禾」——**姓名是猜的**；
- 作品名取自一份写死的示例标题数组——**作品名是假的**；
- 日期写死 `2026.08.11`——**课次日期是假的**。

而所有下游产物都建立在这个猜测上：班级海报上的学员姓名（`tasks/prd-share-poster.md` US-305）、班级视频集锦的姓名卡（`tasks/prd-archive-share.md` US-218）、班级点评的归属。**这是整条链路最靠前的错误数据源。**

### 0.2 第一步的下拉是硬编码 DOM，靠命令式补丁灌数据

- `main.jsx:601` 第一步的班级与学员 `<option>` 全部是**写死的字符串**（「周六创意绘画 2 班」「陈一诺 · 7岁」…）。
- 真实数据靠一段 `useEffect`（`main.jsx:308-331`）用 `classSelect.replaceChildren(...)` **直接操作 DOM** 灌进去，并手写 `addEventListener` 同步状态。
- React 声明式与命令式 DOM 混写，任何一次重渲染都可能把真实选项覆盖回硬编码值。

### 0.3 没有课次实体，五份 PRD 都在等它

- 第一步只选「班级 + 学员」，**没有课次日期、没有课程、没有课时序号、没有课题**。
- 课题在第三步从**写死的 8 个字符串**里选（`main.jsx:603` 的 `<select>`）。
- `seedClasses` 里其实已有 `course` 字段（`创意绘画` / `色彩启蒙`），但没有被任何流程使用。
- 直接后果：`tasks/prd-archive-share.md` 的 Q1 只能退化成「班级 + 日期 + 学员 + 作品名」拼 key，导致**一天两节课会被判成同一次更新**。

### 0.4 连带发现：装裱展签的「创作于」日期取的是归档当天

`main.jsx:363` 的 `framePlaque()`：

```js
date: activeFrame?.plaqueDate || new Date().toISOString().slice(0, 10).replace(/-/g, '.')
```

内置装裱预设的 `plaqueDate` 均为空串，所以展签上「创作于」用的就是**归档当下的系统日期**。老师周一补上周五那节课的反馈，展签会写成本周的日期。**这个 bug 只有等课次实体建立后才能根治。**

### 0.5 已经存在一份更好的参考实现（未被使用）

`main.jsx:1521` 的 `StepLesson`（旧 `CreateFlow` 使用）已经具备：**校区 + 班级 + 课程主题 + 教学目标 + 参与学员（全选 / 多选）**。它没被课后反馈流程复用，属于两份实现并行。本次应把它收敛进来，而不是再写第三份。

### 0.6 现有可用的数据与策略

- 学员与班级数据源：`prototype/src/data/studentManagement.js`（`seedStudents` / `seedClasses`，含 `guardianPhone`、`capacity`、`schedule`、`teacher`）。
- 草稿策略：`localStorage['xinlehui-feedback-draft']` **只存元数据**（`{step, media:{id,name,type,size,storage}}`），不存图片本体；`resetDraft()` 清空全部（`main.jsx:334 / :494`）。
- 上传读取：`readFiles(kind, fileList, input)`（`main.jsx:463`）已区分个人与批量，但批量结果没有学员归属。

## 1. Introduction / Overview

课后反馈的第一步，是整个产品**唯一一次把「现实世界的课堂」翻译成「数据结构」的机会**。这一步错了，后面每一步都在错误的基线上工作：装裱展签会写错日期，点评会引用错误的课题，归档会把两节课合成一条，班级海报会把作品标到别人孩子名下。

现在的第一步只有两个下拉框和两个上传按钮，而且最关键的「哪幅画是谁的」这个问题，是用取模猜出来的。

本期把第一步重建为**一次严肃但不繁琐的课堂登记**：

老师选班级、选课程、确认课次日期与课时序号、确认本次课题、勾选参与学员（含缺课标记），然后**按学员逐个上传作品与课堂照片**——每位孩子的画从进入系统的那一刻起就带着正确的姓名、课次与日期。

同时建立两个地基：

1. **课次实体（lesson）**：本次课的权威记录，产出 `lessonId`，作为后续四步流程与全部产物（装裱展签、点评、归档、报告、视频、海报）的唯一上下文。
2. **课程库**：管理端维护课程（名称、年龄段、课时总数、默认课题），老师选课程、确认课题，不再从写死的字符串里挑。

**贯穿始终的红线（继承主 PRD）：** 儿童素材**不落盘**——草稿只存元数据，素材仅存在于当前操作会话；第一步只收**作品与课堂照片**，不收课堂视频（与归档 PRD 的「不做课堂视频混剪」保持一致）。

## 2. Goals

- **G1** 彻底消除「姓名靠取模猜、作品名写死、日期写死」——作品与学员**强绑定**，错配事故降为 0。
- **G2** 第一步产出一个**课次实体**（`lessonId`），带班级、课程、课次日期、课时序号、课题、参与学员与出席状态。
- **G3** 建立**课程库**（管理端维护），老师选课程并确认本次课题，课题不再是写死的 8 个字符串。
- **G4** 装裱展签、点评上下文、归档记录、报告与海报的日期，全部改为**取课次日期**，不再取系统当天。
- **G5** 班级反馈下支持**按学员逐个上传**作品与照片（每人可多幅、可填作品名），18 人班的完整录入 ≤ 3 分钟。
- **G6** 支持**缺课标记**：标记缺课的学员仍生成课次记录，供成长档案产出缺课留白。
- **G7** 第一步填写耗时：个人反馈 ≤ 60 秒；表单默认值合理，老师多数情况下只需确认。
- **G8** 草稿**只存元数据**（班级 / 课程 / 课次 / 学员 / 步骤），素材不落盘；恢复草稿时明确提示需重新选择素材。
- **G9** 收敛重复实现：删掉第一步的硬编码 `<option>` 与命令式 `replaceChildren`，合并 `StepLesson`，全站只保留一份。
- **G10** 前置校验前置到第一步：缺班级、缺课程、缺课次日期、无参与学员、无作品时**不得进入第二步**，并说明原因。

## 3. 角色与关键术语

| 角色 | 能做什么 |
|---|---|
| 老师 | 选择班级与课程、确认课次信息、勾选参与学员、按学员上传作品与照片、保存草稿 |
| 教研 / 机构管理员 | 维护课程库（课程名、年龄段、课时总数、默认课题）、查看课次录入完整度 |
| 平台管理员 | 维护校区与班级基础数据、上传规则上限、素材隐私策略 |
| 家长 | **不参与**本步（家长不能替孩子上传作品） |

| 术语 | 定义 |
|---|---|
| **课次（lesson）** | 一个班级在某一天上的某一次课，是本产品的核心上下文实体，产出 `lessonId`。 |
| **课时序号（lessonNo）** | 本次课是该班级/课程的第几次课（如第 12 次），用于展示与排重。 |
| **课程库（course）** | 管理端维护的课程定义：名称、年龄段、课时总数、默认课题。 |
| **参与学员（participant）** | 本次课实际到场的学员清单，带出席状态（出席 / 缺课 / 补课）。 |
| **作品绑定（artwork binding）** | 一幅作品属于哪一位学员、哪一次课、叫什么名字——**必须显式指定，禁止推断**。 |
| **草稿（draft）** | 只含元数据的未完成记录；素材不进入草稿。 |

### US-401：课次实体与数据模型

**Description:** 作为开发者，我需要一个能唯一标识「某班某天某次课」的实体，它是后面所有功能的上下文。

**Acceptance Criteria:**
- [ ] 定义 `lesson` 结构：`lessonId / orgId / campusId / classId / courseId / lessonNo / lessonDate / topic / objectives / teacherId / participants[] / status / timestamps`
- [ ] `participants[]` 每项含：`studentId / name / attendance(present|absent|makeup) / artworkIds[] / photoIds[]`
- [ ] 唯一性规则：`classId + lessonDate + lessonNo` 班内唯一，重复创建必须被拒绝并给出提示
- [ ] `status` 状态机：`draft → collecting → processing → reviewing → archived`，不可跳变
- [ ] 提供按 `lessonId` 读取与更新、按 `classId + 日期范围` 查询列表的能力
- [ ] 旧数据（无课次的历史归档记录）读取时能兼容映射，不报错、不丢数据
- [ ] `pnpm run build` 通过

## 6. Functional Requirements

### A. 课次实体

- **FR-401** 必须定义 `lesson` 实体，字段至少包含：`lessonId / orgId / campusId / classId / courseId / lessonNo / lessonDate / topic / objectives / teacherId / participants[] / status / timestamps`。

- **FR-404** `status` 必须为 `draft / collecting / processing / reviewing / archived` 且不可跳变。
- **FR-405** 必须支持按 `lessonId` 读写、按 `classId + 日期范围` 查询。
- **FR-406** 历史无课次数据必须能兼容映射，不得因缺字段报错或丢数据。

## 8. Design Considerations

### 8.1 交互原则

- 第一步的默认值要**尽量正确**：班级默认上次用的班、日期默认今天、课时序号自动推荐、课题取课程默认值——老师多数情况下只需要「确认」。
- 表单分三段（**课次信息 → 参与学员 → 素材上传**），每段完成后再展开下一段，避免一屏堆 18 个上传位把老师吓到。
- 学员选择用大点击区的卡片网格（参考现有 `student-select` 样式），不用多选下拉。
- 「学员 × 上传位」列表必须让老师**一眼看出谁还没传**：已传与未传用明显的状态色区分，并显示「还有 3 位学员未上传作品」。

### 8.2 视觉与品牌

- 沿用暖金 `#CFA52E`、墨黑 `#2B271F`、暖白 `#FBF8F2`；**不使用蓝色作为主视觉**。
- 缺课学员用**温柔的留白卡片**呈现（呼应现有 `GentleAbsence` 的语气），不要用红色警示色。

### 8.3 移动端

- 手机上「学员 × 上传位」为单列卡片流，每张卡片含姓名、缩略图、上传按钮与作品名输入。
- 支持连续拍摄/连续选择，减少来回滚动。
- 顶部固定一个「X/Y 已上传」进度条，随时知道还剩多少。

### 8.4 复用现有组件

- 学员卡片网格复用现有 `.student-select label` 样式（`styles.css`）。
- 上传交互复用 `readFiles()`（`main.jsx:463`）的读取逻辑，但结果必须带学员归属。
- 课次表单参考 `StepLesson`（`main.jsx:1521`）已有的字段与布局，**合并而非重写**。
- 班级与学员数据沿用 `studentManagement.js`（`seedClasses.teacher` 已可用于权限过滤）。

### 9.2 关键技术决策

1. **课次是上下文，不是附件**：所有下游数据都挂 `lessonId`，而不是各自拼 key。这是消除前四份 PRD 里所有「退化唯一键」的根本手段。
2. **绑定必须显式**：作品与学员的对应关系只能由老师操作产生，**任何推断（下标、文件名、AI 猜测）都不允许**。这是本次最重要的正确性约束。
3. **草稿分层**：元数据可持久化（localStorage），素材不可（会话内 object URL）。既保住了"不用重新选班级"的体验，也守住了"儿童素材不长留浏览器"的隐私红线。
4. **上传结果带归属**：`readFiles()` 的返回值从 `File[]` 升级为 `{ file, studentId }[]`，从数据结构层面杜绝错配。
5. **展签日期统一来源**：`lesson.lessonDate` 是唯一日期来源；装裱模板里的 `plaqueDate` 降级为「显示格式与位置配置」，不再承载具体日期值（需同步更新 `tasks/prd-smart-framing-v2.md`）。
6. **课程库最小可用**：只做「课程名 / 年龄段 / 课时总数 / 默认课题（可分课时）」，不做教学大纲全文与教研内容库（那是另一个模块）。
7. **收敛而非叠加**：第一步现在有两份实现（`TeacherFlowV2` 内联 + `StepLesson`），必须先合并再改，否则每改一次要改两处。
