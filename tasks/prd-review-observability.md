## 0. 这份 PRD 要解决的到底是什么（与既有实现的关系）

五维点评的**云端视觉模型链路已经跑通**了，但它现在是一个「黑箱」：老师点一下，等 20 秒，出来五段话，然后只能选择信或不信。

现有实现（`prototype/src/services/llmReview.js`）：

- 用 `buildPersonaSystemPrompt()` 把**人设 + 技能库 + 长期记忆 + 观察词候选清单 + 写作要求 + 输出格式**拼成一整段 system 提示词。
- 用 `streamArtworkReview()` 流式调用**硬编码模型** `REVIEW_MODEL = 'glm-5.3-flash'`，把作品与课堂照片作为 `image_url` 传入。
- 思考链其实**已经被捕获**（`delta.reasoning_content` → `reviewStream.reasoning`），并在 `ReviewStreamPanel` 里显示——但默认就是**展开**的，而且只有「AI 思考过程」这一块。
- 观察词目前**双重硬编码**在 `prototype/src/data/reviewKeywords.js`：同一份目录同时喂给前端面板和提示词。
- 存在一条 `fillLocalDraft`「云端不可用？使用本地草稿模板」**降级路径**，会产出不带大模型参与的正文。

**本次要补的四件事：**

1. **把黑箱打开**：老师能看到这次点评到底加载了什么——推理过程、调用了哪些技能、加载了哪些记忆文件、加载了 `agent.md`、拼装了哪些提示词模块，以及模型与参数、耗时与用量。**默认折叠**，需要时展开看全文。
2. **老师能选模型**：不再硬编码，老师可以在机构为该任务启用的视觉模型里选用与切换。
3. **必须用大模型**：删掉本地草稿降级路径，没成功生成就不允许归档。
4. **观察词由管理端维护**：词表从代码里搬进模板，默认把老师端现有的词表导入成模板内容，并支持管理端用大模型提示补充词条。

> 一句话：**从「老师只能看结果」升级为「老师能看清模型依据什么得出这个结果」。**

## 1. Introduction / Overview

五维点评是这套产品里**唯一直接对孩子下判断**的环节。主 PRD 写得很清楚：点评必须有依据、能回到作品、不能用空泛表扬、不能给孩子贴标签。可是当老师只看到五段成品文字时，他没有任何办法验证这句话是从哪来的——是看了画面里的颜色关系，还是模型顺手编了一句「专注投入」。

对机构来说还有第二层问题：教研沉淀的观察口径（人设、技能、记忆、提示词写法）目前**藏在代码和数据库字段里**，没有人能完整看到一次点评到底用了哪些口径，也就无法复盘「为什么这次的点评偏了」。

本期把点评从「黑箱输出」改造成**可观测的推理过程**：

老师在生成点评时，可以展开一个「本次点评详情」面板，看到模型完整的思考链、本次加载的全部文件与技能清单（含版本号与字符数）、拼装后的提示词全文、使用的模型与参数、耗时与 token 用量，以及模型返回的原始 JSON。面板**默认折叠**，只留一行摘要，不干扰日常使用。

同时，点评模型从硬编码改为**老师可选可切换**；本地草稿降级路径被移除，**未成功调用大模型就不得归档**；作品观察词从 `reviewKeywords.js` 搬到**管理端可维护的模板**，默认把现有词表导入为模板 v1，并提供「AI 补充观察词」的候选—采纳流程。

**贯穿始终的红线与主 PRD 一致：** AI 只产出草稿与依据，老师保有判断、修改与发布权；不做心理、医学、人格诊断；证据不足必须写明局限。

## 2. Goals

- **G1** 老师能在**不离开点评页**的前提下，展开查看一次点评的完整推理过程、加载清单、提示词全文、模型参数与用量。
- **G2** 面板**默认折叠**，折叠态提供一行可读摘要（加载了什么 + 用了哪个模型 + 花了多久），展开动作不超过 1 次点击。
- **G3** 能明确回答「这次调用了哪些技能、为什么某项技能没被加载（未勾选 / 已停用 / 不存在）」。
- **G4** 能明确回答「这次加载了哪些记忆文件、哪些 `agent.md`、各自的版本号与字符数」，并可查看全文。
- **G5** 能查看拼装后的 system / user 提示词全文，且能按模块（身份 / 信念 / 说话风格 / 边界 / 技能 / 记忆 / 观察词 / 写作要求 / 输出格式）分段对应。
- **G6** 老师可在机构启用的视觉模型中选择与切换模型，切换后重新生成，且两次生成可对比。
- **G7** **移除本地草稿降级**：未成功调用大模型的点评不得进入五维正文、不得归档、不得对家长可见。
- **G8** 作品观察词改由**管理端模板**驱动；老师端零硬编码；默认把现有 14 组 84 个词导入为平台默认模板 v1。
- **G9** 管理端可用大模型生成观察词候选，**逐条采纳**后写入模板，模板带版本号且可回滚。
- **G10** 推理轨迹留档可审计，但**家长端与家长分享页永不可见**；儿童素材像素不进入轨迹存储。

## 3. 角色与关键术语

| 角色 | 能做什么 |
|---|---|
| 老师 | 选模型、生成点评、展开查看推理全过程、复制/导出详情、编辑正文、归档 |
| 教研 / 机构管理员 | 维护观察词模板、`agent.md`、记忆文件；用 AI 补充观察词；查看本机构的点评轨迹 |
| 平台管理员 | 维护平台级模板与文件、模型授权、提示词披露总开关、轨迹保留期 |
| 家长 | **只读成品点评**，永远看不到推理轨迹、提示词、记忆文件 |

| 术语 | 定义 |
|---|---|
| **推理轨迹（reviewTrace）** | 一次点评生成的结构化留档：模型与参数、加载清单、提示词全文、推理过程、输出原文、耗时与用量、状态与错误。 |
| **加载清单（loaded）** | 本次真正进入提示词的东西：`agent.md`、记忆文件、技能、观察词模板、提示词模块。每一项带来源、版本、字符数、是否命中。 |
| **agent.md** | 机构 / 老师级的 agent 指令文件，内容会作为 system 提示词的前置段落。可版本化、可启停。 |
| **记忆文件** | 按「学员 / 班级 / 机构」分文件维护的长期记忆（如 `memory/students/陈一诺.md`），按上下文自动加载。 |
| **提示词模块（prompt module）** | system 提示词被拆分后的可命名段落，例如 `identity`、`beliefs`、`skills`、`memory`、`keyword_candidates`、`writing_rules`、`output_format`。 |
| **观察词模板** | 管理端维护的分组词表（分组 + 词条），老师端面板与提示词候选清单**共用同一份模板**。 |
| **披露开关** | 平台级配置 `allowPromptDisclosure`：是否允许老师查看提示词正文，默认开。 |

## 5. User Stories

> **验收约定（所有 UI 故事通用）**
> - 每个 UI 故事的最后两条固定验收为：① 在 `prototype/` 下执行 `pnpm run build` 通过；② **在浏览器中真机验证**（`pnpm run dev` → `http://127.0.0.1:5173` → 老师登录 → 课后反馈 → 五维点评），可用 `control-browser` / `web-gui-tester` / `headless-visual-qa` skill 执行。
> - 「真机验证」必须包含手机宽度（390px）下的检查。
> - 涉及推理长文本的故事，必须同时验证「折叠态不卡顿」与「展开后不丢内容」。

### US-101：提示词模块化重构

**Description:** 作为开发者，我需要把现在拼成一整段的 system 提示词拆成有名字、有版本的模块，否则「加载了哪些提示词」根本无从展示。

**Acceptance Criteria:**
- [ ] `buildPersonaSystemPrompt()` 保持**向后兼容**（仍可返回字符串），同时新增一个返回结构的入口，形如 `{ system: string, modules: [{ id, title, content, version, source, chars }] }`
- [ ] 模块 id 至少覆盖：`base_role`、`identity`、`beliefs`、`tone`、`boundaries`、`skills`、`memory`、`agent_md`、`keyword_candidates`、`keyword_rules`、`task`、`writing_rules`、`output_format`、`subject`
- [ ] 模块拼接顺序固定且可断言（同样的输入永远得到同样的 system 字符串）
- [ ] 现有 `streamArtworkReview()` 行为不变：调用方不传新参数时，产出的提示词与改造前**逐字符一致**（用快照测试保证）
- [ ] `pnpm run build` 通过

### US-102：推理轨迹数据模型与采集

**Description:** 作为开发者，我需要一次点评生成的所有关键信息都被结构化记录下来，后面的展示、审计、复现全都依赖它。

**Acceptance Criteria:**
- [ ] 定义 `reviewTrace` 结构：`traceId / parentTraceId / task / studentId / lessonId / model / timing / usage / loaded / prompts / reasoning / output / status / error / createdAt`
- [ ] `timing` 至少记录：排队时间、开始时间、**首字延迟**、思考耗时、总耗时
- [ ] `usage` 至少记录：prompt / completion / reasoning / total tokens 与单次预估成本
- [ ] `reasoning` 保存**全量**思考链（不是截断版），`output.raw` 保存模型返回的原始 JSON 字符串
- [ ] 生成失败或老师中途停止时，轨迹同样落库，`status` 为 `failed` / `aborted`，并记录错误码与可读文案
- [ ] **图片像素不进入轨迹**：`prompts.user` 中的图片只记录引用（附件序号 + 文件 id + 内容 hash），不存 base64
- [ ] 轨迹在生成过程中只驻留内存，**归档时**才提交云端；未归档的轨迹不落盘（沿用现有「草稿只存元数据」隐私策略）
- [ ] `pnpm run build` 通过

### US-103：本次点评详情面板（默认折叠）

**Description:** 作为老师，我平时不需要看这么多细节，但我想看的时候，一次点击就能看到全部。

**Acceptance Criteria:**
- [ ] 面板位于老师端第三步五维点评页，**默认折叠**；折叠态显示一行摘要：`已加载 agent.md v3 · 5 项技能 · 2 个记忆文件 · 观察词模板 v3 · 模型 glm-5.3-flash · 19.8s`
- [ ] 点击摘要行展开为六个分区：**推理过程 / 加载清单 / 提示词 / 模型与参数 / 用量与耗时 / 输出原文**
- [ ] 生成中：摘要行显示实时状态（已用时、思考字数、正文进度），展开后推理过程**逐字流式追加**
- [ ] 生成失败：摘要行显示失败状态与错误文案，展开后可看到失败前的推理增量与错误详情
- [ ] 面板可再次折叠，折叠后再展开不丢失内容（不重新请求模型）
- [ ] 展开态提供「复制全部」与「导出 JSON / Markdown」
- [ ] 家长端与家长分享页**不存在**该面板的任何入口
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：生成一次点评 → 折叠态 → 展开 → 逐区检查 → 折叠 → 再展开，内容一致

### US-104：技能调用可见

**Description:** 作为教研，我想知道这次点评到底用了哪几项技能，没用上的又是为什么。

**Acceptance Criteria:**
- [ ] 面板「加载清单」列出**全部**技能，每条显示：技能名、分类、来源（技能库）、版本或更新时间、字符数
- [ ] 每项标注 `included: true/false` 与**不加载的原因**：`未被人设勾选` / `技能已在库中停用` / `技能 id 在库中不存在`
- [ ] 点开单项可查看该技能进入提示词的**原文片段**
- [ ] 技能清单与提示词中「已启用技能」段落**完全一致**（同一来源，不允许两处各自计算）
- [ ] 人设一个技能都没勾时，明确显示「本次未启用任何技能」而不是空白
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：停用一项技能后重新生成，确认该技能变为「已停用」且不出现在提示词里

### US-105：agent.md 与记忆文件的加载规则与版本化

**Description:** 作为开发者，我需要一套确定的加载规则，让「加载了什么」是可预测、可复现的。

**Acceptance Criteria:**
- [ ] 定义加载顺序：平台级 `agent.md` → 机构级 `agent.md` → 老师级 `agent.md` → 技能模块 → 记忆文件（学员 > 班级 > 机构）→ 观察词模板候选 → 写作要求与输出格式
- [ ] 记忆文件按 `studentId / classId / orgId` 匹配生效范围，同一层级最多加载 N 个（默认 5），按「最近更新 + 相关度」排序
- [ ] 存在**总量上限**（默认 8000 字符）；超限时按优先级截断，并在轨迹中标记 `truncated: true` 与截断位置
- [ ] 每个文件记录 `version`、`chars`、`hash`（sha256 前 16 位）；同样的文件版本必须得到同样的提示词
- [ ] 文件内容支持变量占位符 `{学员名}` `{班级名}` `{老师姓名}` `{课次日期}`，替换结果进入轨迹（记录替换后的正文）
- [ ] 文件被停用或删除后，不再出现在新生成的轨迹里，但**历史轨迹仍能在审计中复现当时的正文**
- [ ] `pnpm run build` 通过

### US-106：管理端 —— agent.md 与记忆文件管理

**Description:** 作为教研，我要能直接维护这些文件和它们的作用范围，不用找开发改代码。

**Acceptance Criteria:**
- [ ] 管理端新增「Agent 指令与记忆」页，左侧按类型与生效范围分组（平台 `agent.md` / 机构 `agent.md` / 老师 `agent.md` / 学员记忆 / 班级记忆 / 机构记忆），右侧编辑器 + 预览
- [ ] 支持新建、编辑、启停、删除、复制为副本；每保存一次 `version` 自增
- [ ] 编辑器提供 Markdown 编辑与预览，并显示实时字符数
- [ ] 提供「拼装预览」：选择一位学员 + 一节课，实时看到这些文件会拼成什么样的 system 提示词（与老师端实际加载使用同一个拼装函数）
- [ ] 提供敏感内容校验：正文包含手机号、微信号等联系方式时给出阻断提示（与「水印禁止写入联系方式」规则一致）
- [ ] 版本历史可查看、可对比、可回滚到任一历史版本
- [ ] 权限：平台级仅平台管理员可写；机构级仅本机构管理员；老师级仅本人；其余只读
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：改一次 `agent.md` → 老师端重新生成 → 确认轨迹里版本号与正文都变了

### US-107：老师端模型选择器与切换

**Description:** 作为老师，我希望知道有哪些模型可用、各自什么特点，并能自己选一个用。

**Acceptance Criteria:**
- [ ] 五维点评生成前提供模型选择器，选项**只包含**「能力标签含视觉理解」且「已启用」且「机构已授权用于点评任务」的模型
- [ ] 每个选项显示：模型名、供应商、版本、能力标签、单价、近期 P95 耗时、健康状态

## 6. Functional Requirements

### A. 提示词模块化与轨迹采集

- **FR-101** system 提示词必须由**具名模块**拼装而成，每个模块具备 `id / title / content / version / source / chars`。
- **FR-102** 模块拼装顺序固定且可断言；相同输入必须产出逐字符相同的提示词。
- **FR-103** 必须为每次生成创建 `reviewTrace`，字段覆盖：模型与参数、加载清单、提示词全文、推理过程、输出原文、耗时、用量、状态与错误。
- **FR-104** 轨迹必须记录**首字延迟**、思考耗时与总耗时三项独立时间指标。
- **FR-105** 轨迹必须记录 `prompt / completion / reasoning / total` tokens 与单次成本估算。
- **FR-106** 轨迹必须保存模型返回的**原始 JSON 字符串**（含解析告警），用于排查解析失败。
- **FR-107** 生成失败与老师主动停止都必须留档，状态分别为 `failed` / `aborted`。
- **FR-108** 重新生成必须通过 `parentTraceId` 关联上一次，支持两次对比。

### B. 详情面板

- **FR-109** 面板**默认折叠**；折叠态必须显示一行摘要（加载了什么 + 模型 + 耗时）。
- **FR-110** 展开后必须包含六个分区：推理过程、加载清单、提示词、模型与参数、用量与耗时、输出原文。
- **FR-111** 生成中必须实时流式展示推理过程，并显示已用时、思考字数与正文进度。
- **FR-112** 折叠再展开不得丢失或重新拉取内容。
- **FR-113** 展开态必须提供「复制全部」与「导出 JSON / Markdown」。
- **FR-114** 家长端与家长分享页必须**不存在**任何推理轨迹入口，服务端亦须拒绝家长会话查询。

### C. 技能调用可见

- **FR-115** 加载清单必须列出全部技能，含名称、分类、来源、字符数。
- **FR-116** 未加载技能必须给出原因：未勾选 / 已停用 / 不存在。
- **FR-117** 技能清单与提示词中的技能段落必须来自同一次计算，不允许两处各自推导。
- **FR-118** 点开单项技能可查看其进入提示词的原文片段。

### D. agent.md 与记忆文件

- **FR-119** 加载顺序固定为：平台 `agent.md` → 机构 `agent.md` → 老师 `agent.md` → 技能 → 记忆文件（学员 > 班级 > 机构）→ 观察词模板 → 写作要求与输出格式。
- **FR-120** 记忆文件按 `studentId / classId / orgId` 匹配生效范围，同层最多加载 5 个（可配）。
- **FR-121** 存在总量上限（默认 8000 字符），超限按优先级截断并在轨迹标注。
- **FR-122** 每个文件必须记录版本号与内容 hash，保证可复现。
- **FR-123** 文件内容支持变量占位符替换，轨迹保存**替换后**的正文。
- **FR-124** 文件停用或删除后不影响历史轨迹的复现。
- **FR-125** 文件正文必须做敏感信息校验，包含手机号、微信号等联系方式时阻断保存。

### E. 模型选择与切换

- **FR-126** 老师端必须提供模型选择器，选项范围为「视觉理解能力 + 已启用 + 已授权用于点评」的模型。
- **FR-127** 每个模型选项必须展示名称、供应商、版本、能力标签、单价、近期 P95 耗时与健康状态。
- **FR-128** 不可用模型置灰并显示原因。
- **FR-129** 老师的选择必须记住为个人默认，并在下次进入时生效。
- **FR-130** 生成中切换模型必须二次确认，确认后重新生成并产生新轨迹。
- **FR-131** 必须支持「由模型池自动路由」，并在轨迹中标注模型来源。

### F. 强制大模型

- **FR-132** 必须移除全部本地草稿兜底入口与相关样式。
- **FR-133** 五维正文只能由成功的大模型返回写入。
- **FR-134** 归档必须校验「五维全非空 + 轨迹状态成功」，否则禁用并说明原因。
- **FR-135** 失败态必须提供重试、换模型重试、稍后再来三个动作，且不丢失已填写的老师观察。
- **FR-136** 连续失败 3 次必须提示服务波动并推荐健康度最高的可用模型。
- **FR-137** 错误展示必须使用可读文案，不暴露原始错误码。
- **FR-138** 未成功生成的点评不得出现在家长端与分享页。

### G. 观察词模板

- **FR-139** 老师端面板与提示词候选清单必须共用同一份云端模板。
- **FR-140** 首次上线必须把现有 14 组 84 个词导入为平台默认模板 v1，且逐字一致。
- **FR-141** 模板必须支持按模式（个人/班级）、课程类型、年龄段匹配，多套命中时取优先级最高。
- **FR-142** 模板读取失败必须回退内置词表并在界面明示，不得静默降级。
- **FR-143** 模型返回的词必须经过模板校验，模板外的词一律丢弃。
- **FR-144** 管理端必须支持模板的增删改查、启停、排序、复制、导入导出。

## 7. Non-Goals（本期不做）

- **不做家长端可见的推理过程**：家长只看成品点评，任何轨迹、提示词、记忆文件对家长永久不可见。

## 8. Design Considerations

### 8.1 视觉与信息层级

- 面板是「**按需深入**」的设计：折叠时只有一行摘要，绝不占用点评正文的空间与注意力。
- 摘要行必须能回答老师最关心的三个问题：**用了什么模型、加载了什么、花了多久**。
- 六个分区用统一的手风琴样式；每区标题右侧固定显示关键计数（如「技能 5」），让老师不必展开就知道有没有内容。
- 提示词分区用**模块分块 + 段落标题**呈现，不要甩一整块等宽文本给老师看。
- 推理过程用等宽字体、行高放宽，允许长文阅读；不要做逐字高亮动画，避免分散注意力。

### 8.2 交互原则（继承主 PRD）

- **每一步只突出一个核心任务**：点评页的主任务是「老师审阅并编辑五维正文」，推理详情是**次要但仍可达**的信息。
- 生成中不阻塞老师：老师可以边看推理边浏览作品，也可以随时停止。
- 「必须用大模型」这条规则要用**正向表达**告诉老师：不是禁用按钮，而是「正在用 glm-5.3-flash 生成，约 20 秒」。
- 失败态的三个动作要给出**代价差异**（同模型重试快、换模型可能更慢但更稳、稍后再来不消耗额度）。

### 8.3 移动端

- 手机上摘要行固定在点评卡片下方，展开后为全屏抽屉，顶部固定「分区 Tab + 折叠按钮」。
- 长推理文本必须支持"跳到底部"与"回到顶部"快捷按钮。

### 8.4 管理端

- 观察词模板页以「左模板列表 / 中分组与词条 / 右 AI 补充候选」三栏组织，符合「AI 给候选、人做决定」的流程。

### 9.2 关键技术决策

1. **提示词模块化是前置条件**：没有模块清单，就无法展示「加载了哪些提示词」。先重构 `buildPersonaSystemPrompt`，并用快照测试保证改造前后 system 字符串一致。
2. **轨迹只在归档时落库**：生成期间驻留内存，避免「老师试了三次都没发布，云端却存了三份儿童相关提示词」。沿用现有「草稿只存元数据」的隐私策略。
3. **图片只存引用**：`prompts.user` 中图片记录为 `{ type: 'image_ref', ref: 'artwork#1', hash }`，不存 base64，防止轨迹体积爆炸与素材二次落库。
4. **技能清单单一来源**：把「技能解析」抽成一个纯函数，同时喂给提示词拼装与轨迹采集，避免两处计算结果不一致（这是最容易出现"界面说用了5个技能、提示词里其实4个"的地方）。
5. **观察词模板单表 + JSON 分组**：与现有 `framing_presets` 用 `spec` JSON 的风格一致，减少表数量；分组与词条的编辑在前端做数组操作后整体 upsert。若后续需要词条级审计，再拆成行级表。
6. **模型选择受授权约束**：老师能选的模型 = 模型列表（视觉理解 + 已启用）∩ 机构为「点评任务」授权的模型池，保证不会选到未授权或不可用的模型。
7. **流式渲染节流 + 惰性挂载**：推理链可能上千字，逐 chunk 触发 React 渲染会明显卡顿；折叠态不挂载正文 DOM。
8. **披露开关放在平台配置**：`allowPromptDisclosure` 默认开启（本期选择全量明文），但保留治理手段，应对未来机构不希望提示词写法外流的情况。

### 9.4 性能与兼容

- 推理链流式渲染节流 ≥100ms；折叠态惰性挂载。
- 单次点评轨迹（含提示词与思考链全文）预计 20–80KB，归档时压缩存储。
- 现有的 `usage` 采集（`stream_options: { include_usage: true }`）已具备，直接接入轨迹即可。
- 模型切换需要保持 `stream: true` 与 `messages[0]` 为 system 两个已实测的硬约束（见 `llmReview.js` 注释），否则 SDK 直接拒绝。
- 兜底词表保留在代码中作为离线降级，但必须在界面明示，避免"以为在用机构模板、其实用的是内置词表"。

### 9.5 隐私与安全

- 轨迹含学生姓名、课堂观察与机构提示词资产，属于**高敏感数据**：家长端永不可见、老师仅见自己经手的、管理员可审计、保留期可配。
- 儿童素材像素不入轨迹，只存引用与 hash。
- `agent.md` 与记忆文件正文必须做联系方式校验，与同族 PRD `tasks/prd-smart-framing-v2.md` 的 FR-47（水印与落款禁止写入联系方式）保持同一条红线。
- 导出与复制行为必须留审计日志，防止提示词资产被批量带走。

## 12. Open Questions

- **Q1** 轨迹**全量留档的保留期**默认 90 天是否合适？机构可能希望更短（如 30 天）或更长（用于学期复盘）。是否需要"按机构配置"？
- **Q2** 老师能看到 **agent.md 与提示词全文**（已选 1A），是否还需要**水印/溯源**（例如提示词区块显示"内部资料，请勿外传"）？还是完全不做限制？
- **Q3** 本轮 `agent.md` 与记忆文件只做**在线编辑器**维护（Non-Goal 里排除了上传 .md）。教研是否实际需要"上传现成的 .md 文件"？需要的话请告知，我会把它并入 US-106。
- **Q4** 记忆文件与现有 `teacherProfiles.memory` 字段是**并存**（人设页继续可编辑，作为过渡）还是**迁移**（人设页的记忆字段改为只读并指向文件）？本 PRD 默认并存过渡，需要明确下线时间点。
- **Q5** 老师个人默认模型是**存在本机**还是**云端跨设备同步**？（老师换手机/换教室电脑时是否要保持一致）
- **Q6** 「AI 补充观察词」用**哪个模型**？是复用点评的视觉模型（能看作品，但词表补充其实不需要看图），还是走文本模型池？本 PRD 默认走**文本模型池**（更便宜、更快）。
- **Q7** 推理过程与提示词是否需要支持**按角色分级**（例如新老师看不到提示词全文，教研/主教可以看到）？本期按 1A 全员可见，如需分级请告知。
- **Q8** 是否存在**合规要求**需要对提示词与思考链做**定期抽查**（例如每月抽 20 条轨迹由教研复核）？如需要，我会在管理端增加"抽查任务"模块。
- **Q9** 模型切换后，**历史轨迹是否需要保留两次对比视图**（并排 diff 推理与正文）？本 PRD 只提供 `parentTraceId` 关联与基础对比，未做并排视图。
