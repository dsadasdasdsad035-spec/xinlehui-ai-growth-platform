## 0. 现状与已核查的缺口

### 0.1 两个「转发家长」目前都是假的

| 位置 | 现状 | 证据 |
|---|---|---|
| 成长档案 → 一键转发家长 | 点击只弹 toast：「家长版链接已生成，可一键转发作品、照片与点评。」**没有海报、没有图片、没有链接** | `prototype/src/GrowthArchiveData.jsx:54` |
| 学员档案 → 转发家长 | 点击只弹 toast：「已生成《X》的家长分享卡，包含作品、照片和老师点评。」**同样没有产物** | `prototype/src/StudentArchiveData.jsx:21` |

**全仓没有任何海报生成代码**：`grep 海报` 只命中技能市场文案（`skillMarketplace.js`）与个人成长中心的一句入口描述（`main.jsx:849`「课程亮点海报」）。没有 canvas 海报渲染、没有海报模板表、没有管理端页面。

### 0.2 可以直接复用的成熟范式（这是本 PRD 成本最低的原因）

- **模板管理范式**：管理端「装裱设置」页（`FramingSettingsPage`，`main.jsx:1377`）+ 云表 `framing_presets`（`preset_key` 幂等 upsert，`framingPresetsApi.js`）+ `ADMIN_ONLY_PAGES` 权限数组（`main.jsx:1484`）+ admin 侧边栏菜单（`main.jsx:92`）。海报模板**照这套做**即可：管理端维护、老师端选用、参数化、启停排序、权限隔离。
- **Canvas 渲染范式**：`prototype/src/services/framing.js` 的 `renderFramedArtwork`（1800×1360 画布、等比 contain、白底、可选阴影、字号与字距控制、`canvas.toDataURL`）已经在生产路径上跑通；`roomReconstruct.js`、`galleryScene.js` 也有同类实现。海报渲染**沿用同一套写法**，不引入新依赖。

### 0.3 一个必须提前解决的缺口

- **全仓没有 `cloud.storage` 使用先例**（grep 为空）。Q3 选的是参数化模板（不需要上传底图），因此本期**不阻塞**；但机构 Logo、老师签名图、印章图这类图片素材仍需要一个上传去处——要么走对象存储（需新接入），要么内置若干预设 Logo 位并允许填外链。见开放问题 Q4。

## 1. Introduction / Overview

「一键转发家长」是整个产品**面向家长的最后一步**，也是机构服务最容易被看见的一步。现在它是个空按钮：老师点下去，只弹一句提示，家长什么也收不到。

而老师真正想发给家长的东西，其实是一张**体面的图**——作品在中间，孩子的名字在下面，一句老师说的话，加一个能看完整档案的二维码。微信里发一张图，比发一条链接的打开率高得多；机构也终于有了可以被家长转发出去的门面。

本期做三件事：

1. **管理端建海报模板库**：参数化模板（背景、边框、标题、占位区、二维码、Logo 位置全部可配），内置覆盖五类场景的模板，改动即刻对老师端生效。
2. **老师端一键转发即渲染**：点「一键转发家长」弹出模板选择 + **用真实数据实时渲染的预览**，换模板即时重画，满意后导出图片或连同分享链接一起发出去。
3. **两处入口共用一套模板**：成长档案的「一键转发家长」与课后反馈第四步的「转发给家长」走同一条渲染路径，老师不会遇到两种风格。

**贯穿始终的红线（继承主 PRD）：** 海报只做**排版与叠加**——作品图等比缩放、留边、加边框与文字，**绝不重绘、不裁切主体、不调色**；海报只包含**成品素材与老师确认后的点评**，不含原图、不含推理轨迹、不含内部提示词、不含联系方式。

## 2. Goals

- **G1** 点击「一键转发家长」后，能在 **3 秒内**看到一张用该学员真实数据渲染完成的海报预览。
- **G2** 管理端提供**海报模板库**，内置不少于 **8 套**模板，覆盖五类场景（单作品 / 阶段成长 / 班级集体 / 视频封面 / 报告长图）。
- **G3** 模板参数化：新增一套模板**只需在后台改参数**，不需要开发介入、不需要设计切图。
- **G4** 换模板、换作品、改文案时预览**即时重绘**（≤300ms），无需提交或等待。
- **G5** 老师可改标题、寄语金句、日期、是否显示二维码，并「**另存为我的模板**」；不做拖拽编辑器。
- **G6** 导出 PNG（无损）与 JPG（微信友好）两种格式，文件名规范、可直接微信发送。
- **G7** 海报上的二维码指向**有效的家长分享链接**，且分享被撤回后二维码同样失效。
- **G8** 成长档案与课后反馈第四步**共用同一套模板与渲染路径**。
- **G9** 海报渲染**不改变作品像素**，且**不渲染原图**（只用归档后的成品素材）。
- **G10** 管理端编辑模板时能**实时预览**，并在保存前做可扫性、越界、文字溢出三类校验。

## 3. 角色与关键术语

| 角色 | 能做什么 |
|---|---|
| 老师 | 选模板、预览、换作品、改文案、另存为我的模板、导出与转发 |
| 教研 / 机构管理员 | 维护本机构海报模板、预览、启停排序、设为默认 |
| 平台管理员 | 维护平台级模板与内置模板库、配置字体白名单与二维码规则 |
| 家长 | **只读**：收到的是图片与分享链接，不接触模板与编辑能力 |

| 术语 | 定义 |
|---|---|
| **海报模板（poster spec）** | 一套可由 canvas 精确绘制的参数集合：画布、背景、边框、装饰、各占位区（slot）的坐标与样式。**不含具体作品数据**。 |
| **占位区（slot）** | 海报上的一块内容区域，类型为 `image` / `text` / `qrcode` / `logo`，带位置与尺寸比例、以及一个内容模板（如 `《{作品名}》`）。 |
| **比例坐标** | 所有 `x / y / w / h` 与字号都表达为**相对画布短边的比例**，保证同一模板在不同导出尺寸下位置一致。 |
| **五类海报** | `single` 单作品 / `period` 阶段成长 / `class` 班级集体 / `video-cover` 视频封面 / `report-long` 报告长图。 |
| **我的模板** | 老师在系统模板基础上改文案与少量参数后另存出的个人模板，仅本人可见。 |
| **金句（quote）** | 从五维点评里抽取的一句原文，**逐字来自老师确认后的点评**，不改写。 |

### US-301：海报模板数据模型与 Canvas 渲染引擎

**Description:** 作为开发者，我需要一套能用参数描述海报、并能被 canvas 精确画出来的引擎，否则「后台改参数即出新模板」无从实现。

**Acceptance Criteria:**
- [ ] 定义 `poster spec v1`：`version / kind / canvas / background / frame / decor / slots[]`
- [ ] `slots[]` 支持四种类型：`image`、`text`、`qrcode`、`logo`
- [ ] 所有位置与尺寸使用**相对画布短边的比例**（0–1 小数），不使用绝对像素
- [ ] `text` slot 支持：内容模板（含变量）、字体（限白名单）、字号比例、颜色、对齐、最大行数、行高、字距
- [ ] `image` slot 支持：`contain` 适配、白底、圆角比例、可选阴影、可选边框
- [ ] 定义 `normalizePosterSpec(raw)`：字段缺失或非法时回落到默认值，**不抛错**
- [ ] 渲染函数签名固定为 `renderPoster({ spec, data, scale })`，返回 `Blob` 与 `dataURL`
- [ ] 渲染**不修改作品像素**：仅等比缩放与留边，不做裁切、滤镜、重绘
- [ ] `pnpm run build` 通过

### US-302：内置海报模板库（不少于 8 套）

**Description:** 作为老师，我不想从零设计，打开就该有几套好看的可以直接用。

**Acceptance Criteria:**
- [ ] 内置不少于 **8 套**模板，覆盖五类场景，每类至少 1 套、主流场景至少 2 套
- [ ] 命名可读（如「暖金留白 · 单作品」「原木素雅 · 阶段成长」「墨色作品墙 · 班级集体」）
- [ ] 每套模板附带一句说明（适合什么场景、什么色系的作品）
- [ ] 内置模板默认 `enabled: true`、`builtin: true`，且**不可删除**（只可停用）
- [ ] 内置模板随管理端首次加载自动初始化到云端模板表（幂等，重复初始化不产生重复数据）
- [ ] 现有品牌色被正确使用：暖金 `#CFA52E`、墨黑 `#2B271F`、暖白 `#FBF8F2`，**不使用蓝色作为主视觉**
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：管理端模板列表能看到 8 套缩略图，且每套缩略图渲染成功

## 6. Functional Requirements

### A. 模板与渲染引擎

- **FR-301** 海报模板必须用参数化 spec 表达，结构为 `version / kind / canvas / background / frame / decor / slots[]`。
- **FR-302** `slots[]` 必须支持 `image` / `text` / `qrcode` / `logo` 四种类型。
- **FR-303** 所有位置、尺寸与字号必须使用**相对画布短边的比例**，禁止绝对像素定位。
- **FR-304** `text` slot 必须支持内容模板与变量占位符：`{学员名}` `{作品名}` `{周期}` `{日期}` `{老师姓名}` `{机构名}` `{点评金句}`。
- **FR-305** `text` slot 必须支持字体白名单、字号比例、颜色、对齐、**最大行数**与行高、字距。
- **FR-306** `image` slot 必须支持 `contain` 适配、白底、圆角比例、可选阴影与可选边框。
- **FR-307** 必须提供 `normalizePosterSpec(raw)`，非法或缺失字段回落到默认值且不抛错。
- **FR-308** 必须提供统一渲染函数 `renderPoster({ spec, data, scale })`，返回 `Blob` 与 `dataURL`。
- **FR-309** 渲染**不得**裁剪作品主体、不得调色、不得重绘，只允许等比缩放与留边。
- **FR-310** 渲染必须只用归档后的成品素材，**禁止**使用原始拍摄图。
- **FR-311** 文本必须做自动换行与溢出省略，并在预览与导出前给出溢出警告。
- **FR-312** 渲染必须在同一份实现上服务预览与导出，禁止两套代码导致像素不一致。

### B. 五类海报版式规则

- **FR-313** `single` 单作品：1080×1440；作品区占上部约 55%；含作品名、学员名、金句、日期、Logo、二维码。
- **FR-314** `period` 阶段成长：1080×1920；拼贴网格按作品数自适应（4→2×2、6–9→3×3、10–12→3×4）。
- **FR-315** `class` 班级集体：1080×1920；每位学员代表作一格，可标注姓名，默认按班级名单排序。
- **FR-316** `video-cover` 视频封面：1080×1920；含标题、周期、时长角标与播放图标。
- **FR-317** `report-long` 报告长图：1080 宽、高度自适应（≤4096px）；超出时按「降 DPI → 分段出多张」降级。
- **FR-318** 单作品海报的金句必须逐字来自五维点评中老师确认后的内容，不得改写、不得由模型新生成。
- **FR-319** 阶段拼贴与班级作品墙的作品必须 `contain` 适配且标注课次日期（可关闭）。
- **FR-320** 阶段海报作品数超过上限（默认 12）时按课次**均匀精选**，并明确提示「共 N 幅，已收录 M 幅」。
- **FR-321** 班级海报某学员本期无作品时必须保留占位格，不得跳过。
- **FR-322** 班级海报学员数超过上限（默认 30）时必须提示并支持分批出图。
- **FR-323** 所有海报必须预留机构 Logo 位与二维码位（可关闭显示）。
- **FR-324** 海报内不得出现原图、推理轨迹、内部提示词或任何联系方式。
- **FR-325** 海报上**只允许一个二维码**；如需额外展示机构公众号码，必须有明确文字标签区分。
- **FR-326** 报告长图内容必须全部来自归档数据聚合，**禁止**使用写死的示例文案；数据不足时写「数据不足」。

### C. 预览与选用

- **FR-327** 点击「一键转发家长」（两处入口）必须打开海报弹窗，**不得**只返回 toast 提示。
- **FR-328** 弹窗必须左侧展示模板缩略图、右侧展示 1:1 实时预览。
- **FR-329** 模板缩略图必须用**当前真实数据**渲染，不得使用通用示例图。
- **FR-330** 打开弹窗到首张预览完成 ≤3 秒；换模板重绘 ≤300ms。
- **FR-331** 数据来源：成长档案入口用当前学员 + 当前周期；课后反馈入口用本次课次。
- **FR-332** 无归档记录时显示空态与「去创建课后反馈」入口，不渲染空白海报。
- **FR-333** 课后反馈入口下，阶段/班级类模板必须置灰并说明需在成长档案中生成。
- **FR-334** 全仓只允许存在**一份**海报渲染实现，两处入口复用同一组件与函数。

### D. 编辑与我的模板

- **FR-335** 老师可编辑：标题、金句/寄语、日期、是否显示二维码、收录哪些作品。
- **FR-336** 老师不可编辑：版式坐标、字体、配色。
- **FR-337** 编辑时预览必须实时更新，无需点击「应用」。
- **FR-338** 必须支持「另存为我的模板」（`scope='teacher'`，`ownerKey=当前老师`），仅本人可见。
- **FR-339** 个人模板可重命名、可删除；老师不可修改或删除系统/机构模板。
- **FR-340** 个人模板必须与系统模板视觉区分，并在列表上方优先展示。

### E. 导出与分享

- **FR-341** 必须支持导出 PNG（无损）与 JPG（质量 0.9）。
- **FR-342** 文件命名规则：`{学员名}_{作品名或周期}_海报.{png|jpg}`，去除空格与非法字符。
- **FR-343** 导出前必须校验：素材未缺失、二维码不低于可扫阈值、文字未溢出。
- **FR-344** 必须提供「复制微信文案」，内容含学员名与作品名，**不含联系方式**。
- **FR-345** 海报二维码必须指向有效的分享令牌链接，并随分享撤回/过期一并失效。
- **FR-346** 弹窗内必须展示转发状态（未转发 / 已转发 / 已撤回），与归档 PRD 的 US-209 口径一致。
- **FR-347** 导出与转发必须写入审计日志。
- **FR-348** 导出的图片必须支持长按保存与直接分享（iOS Safari 与微信内置浏览器可用）。

### F. 管理端

- **FR-349** 管理端必须新增「海报模板」页，并纳入 admin 菜单与 `ADMIN_ONLY_PAGES` 权限数组。
- **FR-350** 模板列表必须区分系统模板 / 机构模板 / 老师个人模板（只读），并支持启用开关与排序。
- **FR-351** 参数面板必须支持：画布、背景（纯色/线性渐变）、边框、装饰线、每个 slot 的类型与位置尺寸样式、字体与字号比例、二维码尺寸。
- **FR-352** 编辑时必须**实时预览**，预览与实际渲染使用同一个渲染函数。
- **FR-353** 必须支持新增、复制为副本、启用/停用、排序、设为默认模板。
- **FR-354** 必须支持按海报类型与入口配置适用范围。
- **FR-355** 保存前必须校验：slot 是否越界、文字是否可能溢出、二维码是否达到可扫阈值。
- **FR-356** 内置模板必须随首次加载幂等初始化到云端，重复初始化不产生重复数据。
- **FR-357** 内置模板不可删除，只可停用。
- **FR-358** 已被使用过的模板只允许停用，不允许直接删除；删除前提示影响范围。
- **FR-359** 模板变更必须记录 `updated_by / updated_at`，并可查看变更历史。
- **FR-360** 权限：平台级模板仅平台管理员可写；机构级仅本机构管理员；老师仅可写自己的个人模板。

### G. 性能与兼容

- **FR-361** 首张预览渲染 ≤3 秒（1080×1440，桌面与手机均需达标）。
- **FR-362** 换模板重绘 ≤300ms。

## 7. Non-Goals（本期不做）

- **不做拖拽式海报编辑器**：老师只能换模板、换作品、改文案，不能自由移动元素（Q5 = A）。
- **不做底图素材上传**：本期为纯参数化模板；PNG 背景图/边框素材的上传能力列入第二期（Q3 = A）。
- **不做服务端渲染**：本期沿用前端 canvas（Q4 = A）；跨端字体差异由「预览与导出同源」自洽解决。
- **不做生成式 AI 底图**：不调用任何生图模型去"补"海报背景，避免风格不可控与额外成本。
- **不做自定义字体上传**：字体限后台白名单。
- **不做海报模板的对外分享市场**：模板只在平台 / 机构 / 老师三层内流转。
- **不做 PDF 导出**：只出 PNG / JPG。
- **不做家长端自助生成海报**：家长只接收图片与链接。
- **不做海报内的视频嵌入**：视频只能通过二维码进入分享页观看。
- **不做批量一键出全班海报包**：本期支持分批与逐张，不做打包 zip（与归档 PRD 的 Q1 保持一致）。

## 8. Design Considerations

### 8.1 视觉原则

- 沿用品牌色：暖金 `#CFA52E`、墨黑 `#2B271F`、暖白 `#FBF8F2`；**不使用蓝色作为主视觉**。
- 海报是**给家长看的第一眼**：作品必须是主角，装饰只负责收边与呼吸感，禁止花哨堆叠。
- 留白要够：四周至少留出画布短边 6% 的边距，文字不要贴边。
- 字体统一走衬线（标题）+ 无衬线（信息）的组合，延续现有装裱展签的中式克制气质。

### 8.2 交互原则

- 弹窗只做一件事：**给老师一张现在就能发的图**。左侧选模板、右侧看效果、底部导出，三步结束。
- 换模板必须即时可见——老师判断"好不好看"靠的是反复切换，而不是读参数。
- 缩略图必须用真实数据渲染：老师要看的是自己孩子的画放进去长什么样，不是通用示意图。
- 导出前把三类风险说清楚（素材缺失 / 二维码过小 / 文字溢出），不要让老师导出后才发现问题。

### 8.3 移动端

- 手机上模板列表改为横向滑动缩略图条，预览区支持双指缩放看细节。
- 主按钮固定在底部拇指区：`导出图片` / `复制文案` / `转发`。
- 导出的图必须能长按保存到相册，并在界面上给出这句提示。

### 8.4 管理端

- 模板编辑页采用「左列表 / 中参数 / 右预览」三栏，与现有「老师人设」「装裱设置」保持同一种操作语言。
- 参数控件要可视化：颜色用色板、尺寸用滑杆、位置用九宫格 + 微调，避免让管理员手写 JSON。
- 参数面板需提供「还原为默认」与「复制为副本」，鼓励在现成模板上改而不是从零建。

### 8.5 复用现有组件

- 模板管理页复用 `FramingSettingsPage`（`main.jsx:1377`）的三栏结构与预览占位作品逻辑。
- 云表读写复用 `framingPresetsApi.js` 的 `preset_key` 幂等 upsert 与排序约定。
- Canvas 绘制复用 `framing.js` 的图片加载、contain 计算、文字与字距绘制、阴影写法。
- 二维码渲染复用装裱 PRD 中已规划的二维码能力。
- 分享令牌与转发状态复用 `prd-archive-share.md` 的 US-208 / US-209。

### 9.2 关键技术决策

1. **参数化而非底图**（Q3 = A）：与现有 `framing_presets + frameSpec` 完全同构，新增模板零开发成本、可无损缩放、结果可复现；代价是做不出插画/手绘底图，这类需求列入第二期并预留 `background.image` 字段位。
2. **比例坐标**：所有位置与尺寸用「相对画布短边的比例」，保证同一模板在 1080 宽预览与 2160 宽高清导出下**版式完全一致**。
3. **预览与导出同源**：同一个 `renderPoster()` 服务预览与导出，只有 `scale` 参数不同。这是避免"预览好看、导出错位"的唯一可靠做法。
4. **不改变作品像素**：作品图只做 contain 缩放与留边；海报的价值在于排版，不在于修饰孩子的画。
5. **前端渲染**（Q4 = A）：与装裱同架构、原型即可验收、零新增基础设施；手机与桌面看到的是同一张导出的 PNG，天然自洽。
6. **canvas 尺寸保护**：报告长图最容易踩 iOS Safari 的单边像素上限，默认把高度封顶 4096px，超出时「降 DPI → 分段出多张」，并在界面说明。
7. **模板三层 + 个人模板**：`scope = platform | org | teacher`，与装裱 PRD 的模板层级策略保持一致，避免每个需求都发明一套权限模型。
8. **二维码单一来源**：海报上的码必须是分享令牌的链接，与 `prd-archive-share.md` US-208 同源，撤回即失效；不允许出现第二个码。

### 9.4 渲染要点与已知坑

- **作品图必须先解码再绘制**：用 `Image` + `decode()`（或 `onload`）确保尺寸可用；跨域图片需要 `crossOrigin='anonymous'`，否则 `toBlob` 会抛安全错误。
- **中文字体**：canvas 只能用系统已安装字体，白名单需限定为各端都存在的字体族（`serif` / `sans-serif` / `Songti SC` / `Kaiti SC` / `Noto Serif SC`），避免出现方框。
- **文字换行**：中文没有空格，必须按字符逐个测量宽度换行，不能依赖 `\n` 或自动断词。
- **文字溢出**：`maxLines` 超出时截断并加省略号，同时在管理端保存前给出估算警告。
- **canvas 尺寸上限**：iOS Safari 对 canvas 单边与总像素都有上限，长图必须封顶并降级，否则会得到一张空白图（**这是最容易上线后才发现的坑**）。
- **`toBlob` 是异步的**：导出需处理回调与错误，不要用同步 API 假设。
- **二维码尺寸**：小于 120px 时手机扫码成功率显著下降，管理端必须做最小尺寸校验。

### 9.5 性能与兼容

- 预览渲染走低倍率（`scale = 1` = 1080 宽），导出走目标倍率（`scale = 2` = 2160 宽）。
- 缩略图用 `scale = 0.25` 渲染，避免一次性渲染 8 张全尺寸图拖慢弹窗。
- 长图分段渲染后拼接，避免单次 canvas 过大。
- 导出过程放到 `requestIdleCallback` 或分片执行，保证不阻塞交互。
