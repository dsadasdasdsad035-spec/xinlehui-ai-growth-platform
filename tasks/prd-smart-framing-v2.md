## 0. 这份 PRD 要解决的到底是什么（与既有实现的关系）

> **同族 PRD 划分**：老师端课后反馈拆成五份 PRD 维护——**第一步「创建信息」与课次实体**见 `tasks/prd-lesson-intake.md`；本文覆盖**第二步「智能装裱」**；第三步「五维点评」的推理可观测、模型可切换与观察词模板化见 `tasks/prd-review-observability.md`；第四步「归档转发」与成长档案见 `tasks/prd-archive-share.md`；横跨第三/四步的「**一键转发家长海报**」见 `tasks/prd-share-poster.md`。五份的 `US-` / `FR-` 编号互不重叠（`4xx`、`001~013 / 1~47`、`1xx`、`2xx`、`3xx`）。

现有原型里，「智能装裱」已经能跑通一条**全自动**链路，但它是一条**只读**链路：

- 已有：老师旋转整幅原图 → 系统自动裁掉纸外的桌面/地面 → 按后台预设画框合成装裱图（`prototype/src/services/framing.js` 的 `renderFramedArtwork`，画布固定 1800×1360）。
- 已有：后台「装裱设置」可以用自然语言让大模型生成一套画框参数（`prototype/src/services/frameSpec.js`），存云表 `framing_presets`（`prototype/src/services/framingPresetsApi.js`），预置 4 套：星光展 / 自然原木 / 东方雅境 / 新中式水墨。
- 已有：装裱成品会回流到五维点评页与 3D 画廊。

**本次要补的，是把这条只读链路变成老师可掌控的编辑链路**：

1. 老师能**自由裁剪、旋转、放大、缩小**作品，并**保存裁剪后的图片**（现在只有 90° 旋转 + 系统自动裁剪，没有自由裁剪与缩放）。
2. 老师能**挑选相框**，相框有多种样式与材质感（直角 / 圆角 / 半圆 / 斜角；暖黄 / 棕 / 原木 / 墨黑 / 米白）。
3. 老师能设置**水印、落款、时间**的位置与内容。
4. 平台端能把上述一整套配置**保存为模板**，老师端直接套用；老师也可以在此基础上微调并「另存为我的模板」。
5. 一套模板能**批量套用到整班**，落款与展签姓名按学员自动替换。

> 一句话：**从「系统替你装裱」升级为「系统给你一套好用的装裱工作台」。**

## 1. Introduction / Overview

课后反馈是老师每天都要重复的工作。一幅孩子的画从手机拍照到交给家长，中间隔着「拍歪了、桌面上有杂物、作品太小、拍出来没有展览感」这几道坎。现在系统会自动处理，但**老师一旦觉得裁得不对、框不合适、落款位置不好看，就没有任何补救手段**，只能重新上传原图再来一次；机构也没法把「我们机构统一的装裱样式」沉淀下来。

本期在智能装裱环节提供一套**轻量但完整的作品编辑与装裱工作台**：

老师上传作品后，可以像用手机修图一样把作品摆正、裁到满意、放大缩小；再挑一个相框；再把机构 Logo、文字水印、落款、时间放到想要的位置；预览满意后一键保存成高清图或微信可发的压缩图，同时回流到本次课后反馈的作品位，进入成长档案与 3D 画廊。

平台端则把这一整套参数沉淀成**装裱模板**：机构名、Logo、落款字体、时间格式与显示规则、默认相框，全部由平台一次配好，老师端开箱即用，减少每个老师各自摸索。

**贯穿始终的红线（继承主 PRD）：** 装裱只做**框、卡纸、摆正、缩放、裁剪、叠字**，**绝不重绘、不换脸、不改色、不改孩子的线条与笔触**；原图永久保留，任何输出都不覆盖原图。

## 2. Goals

- **G1** 老师可以在不离开课后反馈流程的前提下，独立完成「摆正 → 裁剪 → 缩放 → 选框 → 加水印落款 → 保存」，全程不超过 60 秒。
- **G2** 提供不少于 **8 套**内置相框样式，覆盖形状（直角 / 圆角 / 半圆拱形 / 斜角）与材质色（暖黄 / 深棕 / 原木 / 墨黑 / 米白），且新增样式只需在后台改参数，不需要改代码。
- **G3** 水印（含机构 Logo、文字）、落款（老师姓名、寄语、签名/印章）、时间（默认自动取本次课次日期）三类元素都支持**九宫格定位 + 精细偏移**，位置在不同尺寸作品上保持一致。
- **G4** 平台端可以把一整套装裱配置存为模板并启停、排序；老师端选模板即用，也可微调后「另存为我的模板」。
- **G5** 班级反馈下，一次操作把同一套装裱应用到全班，**落款与展签姓名按学员自动替换**。
- **G6** 裁剪与装裱结果可下载（高清 PNG + 微信友好 JPG），并写回本次课后反馈的作品位，进入成长档案与 3D 画廊。
- **G7** 永远可以一键回到原图；原图、旋转稿、裁剪稿、成品图**分层保存**，任何一步都不覆盖上一层。
- **G8** 手机端单手可完成裁剪与保存（教师端以手机为主设备）。

## 3. 角色与关键术语

| 角色 | 能做什么 |
|---|---|
| 老师 | 编辑作品、选相框、调水印/落款/时间、保存与下载、另存个人模板、批量套用 |
| 机构管理员（校长/教研） | 维护本机构的装裱模板（覆盖平台默认） |
| 平台管理员 | 维护全平台系统模板、内置相框样式库、内置字体白名单、水印与二维码规则 |
| 家长 | **只读**：看到装裱成品（家长端自助装裱不在本期范围） |

| 术语 | 定义 |
|---|---|
| **装裱模板（spec）** | 一套可复用的绘制参数：相框、卡纸、展签、水印、落款、时间、画布。是「怎么装裱」的配方，不含具体作品。 |
| **作品编辑状态（artworkEdit）** | 针对**这一幅**作品的编辑结果：旋转角度、裁剪矩形、缩放、平移。不进入模板，除非老师「另存为我的模板」。 |
| **成品图（framedUrl）** | 模板 + 编辑状态 + 作品 三者合成出的最终图片。 |
| **九宫格位置** | `top-left / top-center / top-right / middle-left / middle-center / middle-right / bottom-left / bottom-center / bottom-right / custom`，配套 `offsetX / offsetY`（相对画布短边的比例）。 |
| **变量占位符** | 模板里写的 `{机构名}`、`{学员名}`、`{作品名}`、`{老师姓名}`、`{课次日期}`，渲染时替换成真实值——这是班级批量自动换名的实现机制。 |

## 5. User Stories

> **验收约定（所有 UI 故事通用）**
> - 每个 UI 故事的最后两条固定验收为：① 在 `prototype/` 下执行 `pnpm run build` 通过；② **在浏览器中真机验证**（`pnpm run dev` → `http://127.0.0.1:5173` → 老师登录 → 课后反馈 → 智能装裱），肉眼确认视觉结果，可用 `control-browser` / `web-gui-tester` / `headless-visual-qa` skill 执行。

### US-001：装裱模板数据模型 v2（含老师个人模板）

**Description:** 作为开发者，我需要一个能表达相框形状、水印、落款、时间与所属层级的模板数据结构，并保证老的 4 套预设继续可用，这样后续所有端都基于同一份 spec 工作。

**Acceptance Criteria:**
- [ ] 定义 `spec v2` 结构，包含 `version`、`frame`（`shape / color / widthRatio / cornerRadiusRatio / lighting`）、`mat`（`color / widthRatio / innerLine`）、`canvas`、`plaque`、`watermark`（`logo / text / qr`）、`signature`、`date`、`art`（`rotateDeg` 默认值）
- [ ] 新增 `normalizeFrameSpecV2(raw)`：所有新字段缺失或非法时**回落到 v1 行为**，不抛错
- [ ] 云表 `framing_presets` 增加 `scope`（`platform` | `org` | `teacher`）与 `owner_key`（机构 id / 老师 id，平台模板为空）两列
- [ ] 现有 4 套内置预设（星光展 / 自然原木 / 东方雅境 / 新中式水墨）迁移后渲染结果与迁移前**像素级一致**（可用同一张测试图比对）
- [ ] 老师个人模板读取时按 `scope='teacher' AND owner_key=当前老师` 过滤，老师看不到别人的个人模板
- [ ] `pnpm run build` 通过

### US-002：相框渲染升级（形状 × 颜色 × 宽度 × 卡纸）

**Description:** 作为老师，我希望相框不只是换颜色，还能是直角、圆角、半圆拱形、斜角，这样同一幅作品可以配出完全不同的气质。

**Acceptance Criteria:**
- [ ] `renderFramedArtwork` 支持 4 种 `frame.shape`：`square`（直角）、`rounded`（圆角）、`arch`（顶部半圆拱形）、`bevel`（四角斜切）
- [ ] 框宽 `frame.widthRatio` 生效范围 0.008–0.08（相对画布短边），越界值被收敛而不是画崩
- [ ] 卡纸 `mat.color` 与 `mat.widthRatio` 独立生效，可选 `mat.innerLine` 细分隔线
- [ ] 相框带轻微高光/暗部（`frame.lighting`），木质与暖金看起来有体积感，不是一块死色
- [ ] 拱形与斜角在**横版、竖版、正方形**三种作品比例下都不出现破图、露底或框宽不均
- [ ] 输出仍为 1800×1360 JPEG（质量 0.92），单次合成耗时 ≤ 800ms（桌面）/ ≤ 1.5s（手机）
- [ ] 不改变任何作品像素：仅等比缩放 + 居中 + 裁剪（裁剪由 US-004 的编辑状态决定）
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：切换 4 种形状逐一截图确认

### US-003：水印 / 落款 / 时间 的可定位绘制

**Description:** 作为老师，我希望把机构 Logo、文字水印、我的落款和创作日期放到画面合适的位置，而不是系统随便丢在角落。

**Acceptance Criteria:**
- [ ] 支持渲染 5 类元素：机构 Logo（图片）、文字水印、落款（文字或手写签名图 + 可选印章）、时间、二维码
- [ ] 每个元素支持九宫格位置 + `offsetX / offsetY` 精细偏移（相对画布短边比例，取值 -0.5–0.5）
- [ ] 文字元素支持字号、颜色、透明度、字体（限后台白名单）、可选旋转角度
- [ ] 内容支持变量占位符替换：`{机构名}` `{学员名}` `{作品名}` `{老师姓名}` `{课次日期}`
- [ ] 时间默认读本次课次日期；`date.source` 支持 `lesson` / `today` / `manual` 三种来源
- [ ] 任一元素关闭（`visible: false`）时**完全不绘制**，不留空白占位
- [ ] 水印/落款区永远不遮挡作品本体超过 15% 面积时给出提示（避免把孩子画挡死）
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：把每个元素依次拖到 9 个位置，确认位置一致、不越界、不裁切文字

### US-004：老师端作品编辑器（旋转 / 裁剪 / 缩放平移）

**Description:** 作为老师，我想在装裱前把作品摆正、裁掉多余部分、放大到合适大小，这样交出去的作品才像是展览品。

**Acceptance Criteria:**
- [ ] 进入智能装裱后，作品区提供「编辑」入口，进入编辑态后显示裁剪框与手势提示
- [ ] 支持：左右旋转 90°、任意角度微调（±15°，步进 0.5°）**（见开放问题 Q6，若只要 90° 步进请确认）**
- [ ] 支持：双指/滚轮缩放（0.5×–5×）、拖动平移、裁剪框 8 点拖拽 + 四边吸附
- [ ] 支持预设比例裁剪：自由 / 1:1 / 4:3 / 3:4 / 16:9 / 原图比例
- [ ] 编辑过程中作品**不得被裁到画布外**：边界有回弹，裁剪框最小尺寸为原图的 10%
- [ ] 编辑态实时预览用低分辨率画布（长边 ≤ 900px）保证跟手，松手后 300ms 内合成高清预览
- [ ] 原图 `originalUrl` 全程只读，编辑结果写入 `artworkEdit`，不修改 `originalUrl`
- [ ] 退出编辑态时若未确认，丢弃本次编辑且给出可撤销提示（Toast）
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：桌面 + 390px 手机宽度各完成一次「旋转 → 裁剪 → 缩放 → 确认」

### US-005：编辑保护 —— 重置 / 撤销 / 一键还原原图

**Description:** 作为老师，我怕手滑把孩子作品的构图裁坏了，必须随时能退回去。

**Acceptance Criteria:**
- [ ] 编辑态提供「撤销」（至少 20 步）与「重做」
- [ ] 「重置」把 `artworkEdit` 恢复为默认（不旋转、不裁剪、1× 缩放、居中）
- [ ] 「回到完整作品」一键还原为系统自动裁剪前的完整画面
- [ ] 任何操作序列后，`原图 → 旋转稿 → 裁剪稿 → 成品图` 四层地址都独立存在，且 `originalUrl` 的哈希值全程不变
- [ ] 刷新页面重新进入后，已确认的编辑状态可恢复（同一会话内），但**不长期保存儿童素材**（沿用现有隐私策略：草稿只存元数据，不存图片本体）
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：连续 10 次编辑 → 全部撤销 → 确认画面回到初始

### US-006：相框样式选择器

**Description:** 作为老师，我想一眼看到有哪些相框、点一下就换，不用懂参数。

**Acceptance Criteria:**
- [ ] 面板以缩略图网格展示相框，每个缩略图用**当前作品**实时渲染（不是通用示例图）
- [ ] 内置不少于 8 套：暖金直角、深棕直角、原木圆角、米白圆角、原木拱形（半圆）、暖金拱形（半圆）、墨黑斜角、暖黄细边
- [ ] 每个样式分为「形状」「材质色」「框宽」三组可调，老师可在选中样式上继续微调
- [ ] 支持卡纸开关与卡纸色选择（暖白 / 米色 / 纸色 / 无）
- [ ] 列表只展示 `enabled !== false` 的模板；后台停用后老师端立即不可选
- [ ] 切换样式时**只重绘装裱，不重跑裁剪**（沿用现有「裁剪与装裱分离」的实现约定）
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：连续切换 8 套样式，确认每套都能正确出图且缩略图同步

### US-007：水印 · 落款 · 时间设置面板

**Description:** 作为老师，我想把机构 Logo、落款和日期放到指定的位置，并且默认值就是对的，不用每次从头设。

**Acceptance Criteria:**
- [ ] 面板分三区：水印（Logo / 文字 / 二维码）、落款（姓名 / 寄语 / 签名或印章）、时间（来源 / 格式 / 位置）
- [ ] 三个区都用同一个九宫格定位控件（F-FRAME-MARK-02），点击格子即定位，拖动可微调
- [ ] 面板内所有输入**实时反映到右侧成品预览**，无需点「应用」
- [ ] 时间默认值 = 本次课次日期（取自课后反馈第一步的课次信息），老师可手动改
- [ ] 落款默认值 = 当前登录老师的姓名；文本域支持变量占位符提示
- [ ] Logo 与二维码支持上传/选择，上传前校验：PNG/JPG、≤512×512、≤200KB，超限给出明确文案
- [ ] 手机端面板以底部抽屉呈现，九宫格点击区域 ≥ 44×44px

## 6. Functional Requirements

### A. 作品编辑与裁剪

- **FR-1** 老师进入课后反馈第二步（智能装裱）后，作品区必须提供「编辑作品」入口；未上传作品时该入口不可用并给出说明。
- **FR-2** 编辑器必须支持：左右旋转 90°、任意角度微调（默认 ±15°，步进 0.5°）、双指/滚轮缩放（0.5×–5×）、拖动平移、裁剪框 8 点拖拽。
- **FR-3** 裁剪比例预设必须包含：自由、1:1、4:3、3:4、16:9、原图比例。
- **FR-4** 裁剪框最小尺寸不得小于原图的 10%；作品不得被拖出画布，越界时回弹。
- **FR-5** 编辑结果必须写入独立的 `artworkEdit` 对象（`rotateDeg / crop{x,y,w,h} / zoom / offsetX / offsetY`），**禁止**写入或覆盖 `originalUrl`。
- **FR-6** 编辑器必须提供撤销（≥20 步）、重做、重置、回到完整作品四个动作。
- **FR-7** 编辑态实时预览使用长边 ≤ 900px 的低分辨率画布；停止操作 300ms 后合成高清预览。
- **FR-8** 未确认退出编辑态时，本次编辑必须被丢弃并给出提示，不得静默保存。

### B. 相框与卡纸

- **FR-9** 相框必须支持 4 种形状：`square` 直角、`rounded` 圆角、`arch` 半圆拱形、`bevel` 斜角。
- **FR-10** 相框材质色必须内置不少于 8 套预设（暖金直角、深棕直角、原木圆角、米白圆角、原木拱形、暖金拱形、墨黑斜角、暖黄细边），并支持任意十六进制自定义色。
- **FR-11** 框宽以「占画布短边比例」表达，取值区间 0.008–0.08，越界自动收敛。
- **FR-12** 相框必须绘制高光与暗部（方向可配），使木质与暖金具备体积感；不得使用位图纹理（本期）。
- **FR-13** 卡纸必须支持颜色、宽度、可选的卡纸内细分隔线，且可以整体关闭。
- **FR-14** 相框与卡纸参数全部来自模板 spec；新增样式必须做到「只改后台参数、不改代码」。
- **FR-15** 切换相框时**只重新合成装裱**，不得重新执行作品裁剪（性能与可预测性要求）。

### C. 水印 / 落款 / 时间 / 二维码

- **FR-16** 必须支持 5 类叠加元素：机构 Logo（图片）、文字水印、落款（文字或签名图 + 可选印章）、时间、二维码。
- **FR-17** 每类元素独立控制显隐、位置、偏移、尺寸、颜色、透明度；关闭时完全不绘制。
- **FR-18** 位置使用九宫格枚举 + `offsetX / offsetY` 比例偏移（-0.5–0.5，相对画布短边），保证跨尺寸一致。
- **FR-19** 文本类元素支持变量占位符：`{机构名}` `{学员名}` `{作品名}` `{老师姓名}` `{课次日期}`；渲染时替换，未命中变量时保留原文并在后台给出警告。
- **FR-20** 时间字段默认来源为「本次课次日期」，可切换为「当天日期」或「手动输入」；格式支持 `YYYY.MM.DD` / `YYYY-MM-DD` / `YYYY年MM月DD日`，并可配置前缀（默认为「创作于 」）与是否显示。
- **FR-21** 落款默认值为当前登录老师姓名；支持寄语（≤60 字）；支持上传手写签名图（PNG 透明底）；印章为可选方形/圆形文字章。
- **FR-22** 上传资源（Logo / 签名 / 二维码底图）必须校验格式与尺寸：PNG/JPG、≤512×512、≤200KB，超限给出明确错误文案。
- **FR-23** 二维码内容由后台统一配置（默认指向该学员的成长档案分享页），老师端不可自由填写 URL，防止外链风险。
- **FR-24** 叠加元素必须绘制在作品之上、相框之下或之上由模板决定（默认：水印与落款绘制在最上层，且不遮挡卡纸与相框区域以外的作品主体）。

### D. 保存与导出

- **FR-25** 「保存图片」必须提供两档输出：高清 PNG（保留裁剪后的原始像素，长边上限 4000px）与微信 JPG（长边 1600px，质量 0.85，体积 ≤ 1MB）。
- **FR-26** 文件名规则：`{学员名}_{作品名}_{课次日期}_装裱.{png|jpg}`，去除空格与非法字符。
- **FR-27** 保存动作必须同时（a）触发本地下载，（b）把成品图写回本次课后反馈的作品位。
- **FR-28** 写回失败不得阻断本地下载，必须提示可重试。
- **FR-29** 每次生成必须记录 `specSnapshot`、`sourceUrl`、`generatedAt`、`operatorId`，保证成品可复现、可追溯。
- **FR-30** 任何输出都不得覆盖原图；`原图 / 旋转稿 / 裁剪稿 / 成品图` 四层地址必须同时存在且互不覆盖。

### E. 模板与平台端

- **FR-31** 模板分三层：`platform`（系统模板）、`org`（机构模板）、`teacher`（老师个人模板）；读取优先级为「老师个人 > 机构 > 平台默认」。
- **FR-32** 平台端必须能把当前全套参数「保存为模板」，支持命名、备注、启停、排序、设为默认。
- **FR-33** 平台端必须支持按课程类型绑定模板；未绑定则使用默认模板。
- **FR-34** 平台端必须维护内置相框样式库（形状 / 颜色 / 框宽 / 高光暗部），新增样式无需开发介入。
- **FR-35** 平台端必须维护字体白名单（沿用现有 `SAFE_FONTS` 思路）、水印与落款的位置枚举、二维码目标配置。
- **FR-36** 平台端保留并升级「自然语言 → 装裱参数」的大模型入口，输出可填充到 v2 字段（形状建议、水印位置建议等）。
- **FR-37** 被引用的模板只允许停用不允许删除；删除前必须提示影响范围。
- **FR-38** 模板变更必须记录操作人与时间，并可查看变更历史。
- **FR-39** 老师端必须能「另存为我的模板」，保存内容为相框 + 卡纸 + 水印 + 落款 + 时间规则，**不含** `artworkEdit`。

### F. 班级批量

- **FR-40** 班级反馈下必须支持「批量应用装裱」：选择模板 → 应用到本班全部已上传作品。
- **FR-41** 批量渲染时 `{学员名}` 与展签姓名必须按作品所属学员自动替换，不得串名。
- **FR-42** 批量操作必须显示进度、可取消、提供失败清单与单项重试；已单独编辑过的作品在覆盖前必须二次确认。
- **FR-43** 18 幅作品批量装裱总耗时 ≤ 20 秒。

### G. 权限与合规

- **FR-44** 写权限：`platform` 模板仅平台管理员，`org` 模板仅本机构管理员，`teacher` 模板仅本人；其余角色只读。
- **FR-45** 服务端必须校验模板写入的 `scope` 与当前用户角色，拒绝越权写入。
- **FR-46** 儿童素材不得写入服务端本地磁盘；上传走私有对象存储并带鉴权，密钥不下发前端。
- **FR-47** 水印与落款内容必须过滤：禁止写入手机号、微信号等个人联系方式（模板层与老师输入层双重校验）。

## 7. Non-Goals（本期不做）

- **不做生成式重绘**：不换背景、不重画线条、不生成式扩图；装裱只做框、卡纸、摆正、缩放、裁剪、叠字。
- **不做调色与滤镜**：不提供饱和度/滤镜/美颜，儿童作品的色彩必须原样保留。
- **不做九宫格材质素材相框**（木纹/布纹/金属位图）：本期用参数化色彩与光影模拟材质，位图素材相框列入第二期。
- **不做 PDF 打印稿与 zip 批量打包**（见开放问题 Q1）。
- **不做视频与课堂照片的装裱**：本次只处理学员作品；照片/视频走各自的处理链路。
- **不做家长端自助装裱**：家长端只读。
- **不做第三方打印、下单与物流对接。**
- **不做水印去除功能。**
- **不做自由的画笔/贴纸/涂鸦**：不允许老师在孩子作品上添加涂鸦内容。
- **不做跨机构模板共享市场**：模板只在平台/机构/老师三层内流转。

## 8. Design Considerations

### 8.1 视觉与品牌

- 沿用品牌色：暖金 `#CFA52E`、墨黑 `#2B271F`、暖白 `#FBF8F2`；**不使用蓝色作为主视觉**。
- 高级感来自留白、克制、细节，不来自复杂装饰：面板控件要少、默认值要准，老师多数情况下**只需要点一下模板**。
- 相框缩略图必须用**当前作品**渲染，让老师看到真实效果，而不是一张通用示意图。

### 8.2 交互原则（继承主 PRD）

- **每一步只突出一个核心任务**：编辑 → 选框 → 加水印落款 → 保存，分成四个可折叠面板，不要把所有控件同时推给老师。
- **默认值即正确答案**：进入智能装裱时，系统已按默认模板出一版成品；老师的动作是「改」，不是「从零做」。
- 自动过程不要求老师点「装裱」「P图」这类按钮；只有**实质性编辑动作**才需要老师主动触发。
- 熊猫伙伴在「装裱完成」「保存成功」两个节点出现，承担情绪反馈，不占用主操作区。

### 8.3 移动端优先

- 面板以底部抽屉呈现，主操作按钮固定在底部拇指区。
- 九宫格定位控件在手机上要能单手点准（≥44×44px），并支持拖动微调。
- 裁剪手势与系统手势冲突时（如 iOS 边缘返回），裁剪框不贴近屏幕边缘。

### 8.4 复用现有组件

- 装裱画布与合成逻辑复用 `prototype/src/services/framing.js` 的 `renderFramedArtwork`（扩展，不重写）。
- 参数收敛与白名单复用 `prototype/src/services/frameSpec.js` 的 `normalizeFrameSpec` 思路，升级为 v2。
- 后台页面复用现有「装裱设置」页（`main.jsx` 中 `FramingSettings` 附近）与其预览占位作品逻辑。

### 9.2 关键技术决策

1. **参数化绘制而非位图相框**：与现有 `frameSpec` 一脉相承，出样式快、无损缩放、可复现；代价是木纹只能用色彩与光影近似。位图素材相框留字段位（`frame.texture`），第二期扩展。
2. **模板与单幅编辑分离**：`spec`（可复用）与 `artworkEdit`（单幅）分开存储，避免「老师裁剪了一幅画，把裁剪参数写进了机构模板」这类事故。
3. **变量占位符驱动批量**：班级批量不写死姓名，而是模板里写 `{学员名}`，渲染时替换——批量与单幅走同一条渲染路径，减少分支。
4. **比例化定位**：所有位置与尺寸用「相对画布短边的比例」表达，保证同一模板在 1800px 合成画布与 4000px 导出图上位置一致。
5. **双画布策略**：编辑用低分辨率预览画布（长边 ≤ 900px）保证跟手，预览稳定后合成 1800×1360 高清成品；导出时按裁剪区域原始像素单独合成一次。
6. **统一云表 + scope 字段**：平台/机构/老师三层模板共用 `framing_presets`，以 `scope + owner_key` 区分，复用现有 upsert（`onConflict: preset_key`）与权限模型，避免两张表双写。

### 9.4 性能与兼容

- 单次高清合成 ≤ 800ms（桌面）/ ≤ 1.5s（手机）；拖动编辑帧率 ≥ 30fps。
- 手机原图先降采样到长边 2400 再进入编辑器，避免内存峰值过高。
- 新增字段必须可选：任何字段缺失时回落到 v1 行为，保证现有 3D 画廊（`prototype/src/services/galleryScene.js`）与五维点评页的既有展示不被破坏。
- 桌面 4000×3000 原图与手机竖图、正方形作品都要覆盖测试。

### 9.5 隐私与安全

- 儿童素材不写服务端本地磁盘；密钥不下发前端（沿用现有受控调用原则）。
- 上传资源（Logo / 签名）走私有对象存储 + 鉴权；不做公开可猜测的 URL。
- 二维码目标由后台配置，老师端不可填任意 URL，防止把外部链接印在孩子的作品上。
