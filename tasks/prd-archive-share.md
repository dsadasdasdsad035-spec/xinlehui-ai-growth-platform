## 0. 现状与已核查的缺口（本 PRD 要修的东西）

### 0.1 已经做对的部分

归档**不是空壳，是真的在写数据**：

- `archiveRecord()`（`prototype/src/main.jsx:589`）在归档前校验「线稿提取已完成 + 点评已生成」，然后调用 `createFeedbackRecord()`（`prototype/src/data/feedbackRecords.js`）生成记录并写入 `records` 状态。
- `prototype/src/main.jsx:135/136` 两个 effect 把 `records` **双写 localStorage 与云表 `feedback_records`**；云端按 `record_key` 幂等 upsert，并会清理本地已删除的孤儿行（`prototype/src/services/feedbackRecordsApi.js`）。
- 成长档案页确实读这份数据（`prototype/src/GrowthArchiveData.jsx:44`）。
- 家长端有按监护人手机号匹配孩子的会话逻辑（`createParentSession`）。

### 0.2 五个必须修掉的缺口

| # | 缺口 | 证据 | 后果 |
|---|---|---|---|
| G1 | **个人档案硬编码学员** | `GrowthArchiveData.jsx:44` 写死 `record.student==='陈一诺'` | 换任何其他学员，档案都是空的；班级维度又不过滤班级，把所有记录都塞进来 |
| G2 | **归档后改点评不会更新** | `main.jsx:591` 的 `if(!archived)` 拦住重复归档 | 老师回第三步改完评语再归档，档案里留的还是**第一版**点评 |
| G3 | **图片进不了云端** | `createFeedbackRecord` 取 `cleanUrl\|\|framedUrl`；`feedbackRecordsApi.js` 的 `httpOnly()` 把 `blob:`/`data:` 过滤成空 | 本地有图、云端无图，家长端看到无图档案 |
| G4 | **作品名硬编码** | `createFeedbackRecord` 的 `title:'未命名作品'` | 档案里永远没有真实作品名，装裱展签上的标题也不同步 |
| G5 | **第四步没有归档状态，也没有转发** | `main.jsx:604`：只有 制作成长集锦 / 制作作品集 / 返回五维点评 / 进入成长档案 | 步骤名叫「归档转发」，却既看不到归档结果，也没有任何转发动作 |

### 0.3 两个「假功能」与两份重复实现

- **「制作成长集锦」「制作作品集」是空承诺**：第四步这两个按钮只弹 toast（「任务已创建，等待服务端接入」/「个人作品集任务已创建」），没有产物、没有任务记录、没有落库。而成长档案页本来就有同类生成入口 → 属于重复入口 + 虚假反馈。
- **成长档案有两份重复实现**：`main.jsx:811` 的 `GrowthArchive`（旧，示例文案版）与 `GrowthArchiveData.jsx`（现用，读 records 版）。旧的 `TeacherFlow`（`main.jsx:224`，含「一键转发给家长」）也已不在路由表里（`main.jsx:1487` 映射的是 `TeacherFlowV2`）。这些死代码必须清理，否则后续每个需求都要改两处。

### 0.4「成长档案为什么每次都要生成」的根因

`GrowthArchiveData.jsx:42`：进页面必须选「生成对象 + 生成周期 + 生成内容」，再点「生成{period}{format}」按钮，`setGenerated(true)` 才渲染预览。

- `generated` 只是组件内 `useState(false)`，**不落库、不记忆**；
- 切换对象 / 周期 / 内容任一都会把它重置回 `false`；
- 报告正文（雷达分值、阶段总结、下一阶段规划）目前是**写死的示例文案**，不是从 `records` 聚合出来的。

**结论：它现在不是「档案」，是一台「报告生成器」。** 这与主 PRD「成长档案是持续沉淀、家长随时可看」的定位相冲突，必须拆成两件事：**档案常驻**、**报告才需要生成**。

### 0.5 「成长记录（视频）」现状：从占位到成片

现有实现是一个**纯占位**，不是功能：

- 前端只有 `growth-video-hero` 占位卡片（`prototype/src/flow-v2.css`），写死「作品、课堂高光与老师寄语 · 02:16」，**没有 `<video>` 元素、没有任何成片文件**。
- 全仓没有 `MediaRecorder` / `ffmpeg` / `WebCodecs` / 逐帧录制的任何代码。
- `prototype/server/index.mjs:162`：**视频上传被显式禁用**（返回 503「Video upload needs the production object-storage adapter and is disabled in local memory mode」）。
- 云 SDK 只有 chat / models / database / storage 四个模块，**没有视频合成端点**。
- 第一步「创建信息」已经移除了课堂视频上传（`feedbackRecords.js` 注释：「课后反馈已去掉视频上传」），**课堂影像素材的供应链是断的**。
- 管理端的「视频生成模型池（Seedance 2 / MotionLite）」是**生成式**视频，**不能用于本功能**：它会重绘孩子的作品，直接违反「绝不改变孩子线条与色彩」的红线，且按 ¥1.80/秒计费（一条 2 分钟视频约 216 元）。
- 旧实现还把它排除在总结之外（`main.jsx:776` 的 `show={generated&&format!=='成长记录（视频）'}`），说明它当时就没被当作真功能。

**本次决定（Q1 = B）：只做服务端 ffmpeg 合成。** 这条路径天然满足红线——它是**确定性蒙太奇**（图片按序 + 等比缩放留边 + 转场 + 字幕叠加 + 混音），孩子的作品像素原样呈现，不做任何重绘。

> **一条必须写在前面的硬约束**：当前工程**没有服务端视频能力**，因此本模块的故事**无法在现有原型里端到端验证**。本 PRD 据此把视频模块拆成两半：前端按接口契约实现（提交任务、轮询进度、预览、下载、分享），服务端 ffmpeg 渲染服务单独排期。在服务端就绪之前，原型只允许**明确标注的占位**（例如「演示数据 · 视频服务未接入」），不得再出现「02:16」这类看不出是假的写死数字。

## 1. Introduction / Overview

第四步「归档转发」是老师一节课劳动的收尾，也是家长真正收到东西的地方。现在这一步的问题不是"做得不好"，而是**名不副实**：它既不能确认归档结果，也不能转发；而真正的档案页又要求老师每次重新"生成"一遍。

本期把收尾做成一个**可信、可见、可更新**的闭环：

1. **归档变成可信的写入**：按「学员 + 课次」唯一，重复归档即更新同一条；成品图上传到私有存储换成持久地址；作品名取自装裱展签。
2. **第四步只做两件事**：确认归档结果、转发给家长。移除两个空承诺按钮，生成类动作统一收敛到成长档案页。
3. **转发真实可用**：生成家长分享链接与二维码，含授权校验、有效期与审计，并显示「未转发 / 已转发 / 已撤回」。
4. **档案常驻**：进入成长档案即看到已归档的课次、作品、点评与缺课记录；「生成」只用于生成**阶段报告**（半学期 / 一学期 / 一年度），并把结果落库缓存，下次直接看。

**贯穿始终的红线（继承主 PRD）：** 成长档案只展示**成品素材**（装裱成品图、修正后的课堂照片）与**老师确认后的点评**；**原始拍摄图永不上传、永不展示**；家长端只读；所有 AI 内容必须经老师确认后才可能出现在档案里。

## 2. Goals

- **G1** 老师归档后能在第四步**看到归档结果**：归档时间、课次、作品、点评状态、素材同步状态。
- **G2** 同一课次重复归档 = **更新同一条记录**，家长端永远看到最新版；不允许产生重复记录。
- **G3** 归档的成品图与课堂照片有**持久可访问地址**，家长端不再出现无图或破图。
- **G4** 第四步**只保留「归档状态 + 转发」**；「制作成长集锦 / 制作作品集」从第四步移除。
- **G5** 老师能生成家长分享链接与二维码，并看到**已转发 / 未转发 / 已撤回**状态与时间。
- **G6** 进入成长档案**立即有内容**，无需先点「生成」；对象与周期是**筛选器**而不是生成动作。
- **G7** 「生成阶段报告」的结果**落库缓存**，再次进入直接显示上次结果，并可「更新报告」（版本递增）。
- **G8** 报告内容**全部来自归档数据**，不再出现写死的示例文案；数据不足的维度明确写「数据不足」。
- **G9** 个人档案按**当前学员**展示，班级档案按**当前班级**展示；不再硬编码任何学员名。
- **G10** 清理死代码：两份档案实现与已废弃的 `TeacherFlow` 收敛为一份。
- **G11** 转发受家长授权约束，转发与撤回都有审计留痕。
- **G12** **个人成长视频**：把一位学员在一个周期内的作品，按课次时间线串成一条 **≤2 分钟**的成片（片头 + 作品帧 + 点评金句字幕 + 老师寄语片尾）。
- **G13** **班级视频集锦**：把全班学员的作品**按学员分段**串成一条 **≤5 分钟**的成片，每位学员有姓名卡。
- **G14** 成片由**服务端 ffmpeg** 合成，输出竖屏 H.264 MP4（微信可直接播放）；作品像素只做等比缩放与留边，**绝不重绘**。
- **G15** 超出时长上限时按课次**均匀精选**，并在界面明确告知「本周期共 N 幅，已精选 M 幅收录」。
- **G16** 管理端建立**音乐库**（从授权曲源搜索与下载入库）；成片只能使用**已确认授权**的曲目，并记录授权凭证以便举证。
- **G17** 成片可预览、可下载、可通过家长分享链接播放，并与阶段报告一样**落库、有版本、可重新生成**。

## 3. 角色与关键术语

| 角色 | 能做什么 |
|---|---|
| 老师 | 归档（可重复更新）、查看归档状态、生成并转发家长分享、生成阶段报告 |

| 术语 | 定义 |
|---|---|

| **原始拍摄图** | 老师手机里那张原图。**永不上传、永不展示**，仅存在于老师本地会话。 |

| **阶段报告** | 按周期（半学期 / 一学期 / 一年度）从归档数据聚合出的一份**快照**，需要生成并落库。 |
| **分享令牌（shareToken）** | 家长分享链接中的随机不可猜测标识，带有效期，可撤回。 |

### US-201：归档数据模型修正

**Description:** 作为开发者，我需要一条记录能唯一标识「某位学员的某一节课」，否则"重复归档即更新"根本无从实现。

**Acceptance Criteria:**
- [ ] 记录新增字段：`lessonId`、`courseId`、`classId`、`studentId`、`recordKey`、`archivedAt`、`updatedAt`、`version`
- [ ] `recordKey` 为业务唯一键：优先 `lessonId + studentId`；无课次实体时退化为 `className + date + studentId + title`
- [ ] `id` 不再使用纯时间戳（`feedback-${Date.now()}`），改为由 `recordKey` 派生，保证同一课次重复归档得到同一个 `id`
- [ ] `date` 使用**课次日期**，不再用 `new Date()` 当天
- [ ] `title` 取自装裱展签的作品名（`activeFrame.plaqueTitle`）或老师填写值，**禁止**硬编码 `'未命名作品'`
- [ ] `reviews` 保留五维结构，并新增 `reviewTraceId` 关联第三步的推理轨迹
- [ ] 旧记录（无新字段）读取时能被兼容映射，不报错、不丢数据
- [ ] `pnpm run build` 通过

### US-202：归档幂等可更新

**Description:** 作为老师，我改完点评再归档，档案里应该是新的，而不是我第一次归档的旧版本。

**Acceptance Criteria:**
- [ ] 同一 `recordKey` 再次归档 = **更新同一条记录**，不新增记录；`version` 自增，`updatedAt` 刷新
- [ ] 归档后回到第三步修改任一维度评语，再次点归档，成长档案里显示的是**修改后**的内容
- [ ] 归档按钮文案根据状态变化：未归档为「归档并生成分享」，已归档为「保存修改并更新档案」
- [ ] 更新后给出可验证反馈：`档案已更新（第 2 版）`，并提供「查看档案」入口
- [ ] 不存在任何路径能产生两条 `recordKey` 相同的记录（列表渲染前按 `recordKey` 去重兜底）
- [ ] 云端 upsert 使用 `record_key` 作为冲突键，与现状保持一致
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：归档 → 改点评 → 再归档 → 刷新 → 进入档案确认是新版

### US-203：归档素材持久化

**Description:** 作为老师，我归档后家长点开应该能看到图，而不是一片空白。

**Acceptance Criteria:**

- [ ] 在浏览器中真机验证：搜索 → 试听 → 入库 → 在老师端确认可见（老师端仅见已确认授权的曲目）

### US-221：音乐选用与版权闸门

**Description:** 作为平台方，我必须能证明每一条发给家长的视频，用的音乐是有授权的。

**Acceptance Criteria:**
- [ ] 曲目授权状态为 `pending / confirmed / expired`，**新建入库默认为 `pending`**
- [ ] 老师端**只出现** `confirmed` 且未过期的曲目；`pending` 曲目在老师端不可见
- [ ] 成片记录所用曲目的 id 与**授权凭证快照**（标题 / 来源 / 授权类型 / 到期日），支持事后举证
- [ ] 老师可选择「静音」，且**默认静音**
- [ ] 混音自动 1.5 秒淡入 / 2 秒淡出，并做音量归一化
- [ ] 授权到期后，系统提示「音乐授权已到期，建议更换或静音」，并记录处置结果
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：把一首曲目设为 pending，确认老师端选不到；改为 confirmed 后可选

### US-222：成片的版本、更新与删除

**Description:** 作为老师，我改了作品之后，视频该不该重做，我要有主动权。

**Acceptance Criteria:**
- [ ] 成片落库：`videoKey`（对象 + 周期 + 类型）、`version`、`generatedAt`、`specSnapshot`
- [ ] 归档作品更新后**不自动重出**，界面提示「有 N 幅作品已更新，建议重新生成」
- [ ] 「重新生成」`version` 自增，**保留历史版本**可回看与下载
- [ ] 删除成片只删除成片与渲染中间产物，**不影响归档记录**
- [ ] 归档记录被删除时，级联删除其成片
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：生成 → 改一幅作品 → 出现提示 → 重新生成 → 版本号变化且旧版仍可看

### US-223：视频任务的权限、审计与存储

**Description:** 作为平台方，孩子的视频不能随便被下载，谁做的、谁下的都要查得到。

**Acceptance Criteria:**
- [ ] 只有本班老师可提交与下载成片；管理员可审计；家长仅可通过有效分享链接播放
- [ ] 审计留痕：提交、完成、下载、分享、更换音乐、删除
- [ ] 渲染中间产物与成片的保留期可配，到期清理需可预览影响范围
- [ ] 存储与流量按机构配额受限，超限时阻止新任务并给出提示
- [ ] 成片文件地址使用带签名的临时 URL，且有效期不超过分享有效期
- [ ] `pnpm run build` 通过

### US-224：移动端与弱网

**Description:** 作为用手机的老师，我提交完视频就想锁屏去上课，回来还能看到结果。

**Acceptance Criteria:**
- [ ] 提交后可退出页面甚至锁屏，任务继续；回到档案页能恢复进度
- [ ] 手机端播放器竖屏自适应，支持全屏播放
- [ ] 成片下载在 iOS Safari 与微信内置浏览器可用，或给出明确替代指引（长按保存 / 在浏览器中打开）
- [ ] 弱网下重复点击「生成」不得创建多条任务（幂等 `jobKey`）
- [ ] 390px 宽度下任务卡片、播放器与音乐选择面板不溢出
- [ ] `pnpm run build` 通过
- [ ] 在浏览器中真机验证：390px 下完成「提交 → 离开 → 返回 → 预览 → 下载」

## 6. Functional Requirements

### A. 归档写入

- **FR-201** 归档记录必须包含业务唯一键 `recordKey`（优先 `lessonId + studentId`，退化 `className + date + studentId + title`）。
- **FR-202** 同一 `recordKey` 再次归档必须**更新同一条记录**，`version` 自增，`updatedAt` 刷新。
- **FR-203** `date` 必须使用课次日期，不得使用归档时的系统当天日期。
- **FR-204** `title` 必须来自装裱展签作品名或老师填写值，禁止硬编码占位名。
- **FR-205** 记录必须关联第三步的 `reviewTraceId`，保证点评可追溯。
- **FR-206** 旧记录读取必须向后兼容，不得因缺字段报错或丢数据。
- **FR-207** 渲染归档列表前必须按 `recordKey` 去重兜底。

### B. 素材持久化

- **FR-208** 归档时必须把装裱成品图与修正后的课堂照片上传到私有对象存储，并保存持久 URL 与 `storageKey`。
- **FR-209** **原始拍摄图禁止上传**，归档数据中不得存在 `originalUrl` 字段。
- **FR-210** 写入云端前必须校验地址为 `https://`，非持久地址不得入库。
- **FR-211** 素材上传失败不得阻断归档；须标记 `media.status='pending'` 并支持重试。
- **FR-212** 家长端遇到缺失素材必须显示占位文案，不得出现破图。

### C. 第四步「归档转发」

- **FR-213** 第四步必须移除「制作成长集锦」「制作作品集」及其假反馈 toast。
- **FR-214** 第四步必须展示归档摘要：学员、课次日期、作品名、归档时间、版本、素材状态、点评状态。
- **FR-215** 第四步主操作固定为：转发给家长、进入成长档案。
- **FR-216** 第四步必须提供返回修改点评的入口，并支持修改后更新归档。
- **FR-217** 归档不完整时第四步必须显示未完成状态与具体原因。
- **FR-218** 第四步文案必须统一为「已写入成长档案」，不得出现「本地草稿」等矛盾表述。
- **FR-219** 必须删除已废弃的 `TeacherFlow` 与旧 `GrowthArchive`，全站只保留一份档案实现。

### D. 分享与转发

- **FR-220** 必须支持生成家长分享链接与二维码，链接使用随机不可猜测的 `shareToken`。
- **FR-221** 分享必须支持有效期（默认 30 天，可配置）。
- **FR-222** 生成分享前必须校验家长授权状态；未授权时阻止生成并给出处理入口。
- **FR-223** 必须支持复制链接、下载二维码、复制微信文案三个动作。
- **FR-224** 分享内容只允许包含成品素材与老师确认后的点评；不得包含原图、推理轨迹、提示词、记忆文件。
- **FR-225** 必须支持撤回，撤回后链接立即失效。
- **FR-226** 必须展示转发状态：未转发 / 已转发 / 已撤回，以及转发时间、渠道、打开次数。
- **FR-227** 家长首次打开必须记录并回传 `firstOpenedAt`。
- **FR-228** 转发状态必须持久化，刷新后保持。

### E. 成长档案常驻

- **FR-229** 进入成长档案必须立即呈现已归档内容，不得要求先点「生成」。
- **FR-230** 个人档案按当前选中学员过滤；班级档案按当前班级过滤；禁止硬编码任何学员名。
- **FR-231** 对象与周期必须是筛选器语义：切换只过滤，不重置内容。
- **FR-232** 默认视图必须包含课次时间线、成品作品、课堂照片、五维点评摘要与缺课记录。
- **FR-233** 顶部必须显示档案概况：已归档课次数、作品数、照片数、最近归档时间。
- **FR-234** 必须提供空态、加载态、错误态三态，错误态可重试。

### F. 阶段报告

- **FR-235** 「生成阶段报告」必须选定周期（半学期 / 一学期 / 一年度）与类型（成长集锦 / 作品集 / 成长记录）。
- **FR-236** 报告生成结果必须落库，键为 `reportKey`（学员 + 周期 + 类型），含 `snapshot / generatedAt / generatedBy / version / status`。
- **FR-237** 再次进入时必须直接展示已存在的报告，并标注生成时间与关联课次数。
- **FR-238** 必须支持「更新报告」，`version` 自增并保留历史版本。
- **FR-239** 报告内容必须全部来自归档数据聚合，**禁止**使用写死的示例文案。
- **FR-240** 数据不足的维度必须明确显示「本阶段数据不足」。
- **FR-241** 报告可删除，删除不影响归档记录。
- **FR-242** 班级报告按班级聚合，个人报告按学员聚合。

### G. 权限、授权与审计

- **FR-243** 老师只能归档与转发自己班级的学员记录。
- **FR-244** 家长只能查看自己孩子的记录，服务端强制校验。
- **FR-245** 授权撤回后，已有分享链接必须一并失效。
- **FR-246** 归档创建/更新、分享生成、家长打开、撤回、报告生成必须写入审计日志。
- **FR-247** 管理端必须能按学员、老师、时间、状态查询转发与授权审计。
- **FR-248** 归档数据保留期必须可配，到期清理需可预览影响范围。

### H. 性能

- **FR-249** 档案时间线首屏渲染 ≤ 1 秒（≤50 条记录）。
- **FR-250** 超过 20 条记录必须分页或虚拟滚动。
- **FR-251** 图片必须懒加载并提供缩略图。
- **FR-252** 390px 下第四步与转发弹窗单手可操作，点击区 ≥ 44×44px。
- **FR-253** 弱网下必须支持「先本地归档成功、素材后台上传」并明示同步状态。

### I. 视频合成服务与任务

- **FR-254** 必须提供服务端 ffmpeg 渲染管线，输入为归档成品图与课堂照片，输出 H.264 / AAC 的 MP4。
- **FR-255** 输出默认竖屏 1080×1920、30fps、`yuv420p`，并带 `+faststart`（保证微信内可边下边播）。
- **FR-256** 必须提供任务状态机 `queued / rendering / done / failed / canceled`，并记录进度百分比。
- **FR-257** 任务必须持久化：`jobKey / type / studentId / classId / period / specSnapshot / status / progress / outputUrl / durationSec / bytes / attempts / error / createdBy / 时间戳`。
- **FR-258** 任务必须幂等：同一 `jobKey` 重复提交不得产生多条任务。
- **FR-259** 失败任务必须可重试，并保留已渲染的帧片段以支持断点续渲。
- **FR-260** 必须支持取消进行中的任务，取消后释放渲染资源。
- **FR-261** 必须限制单机构并发渲染数（默认 2），超出排队并显示队列位置。
- **FR-262** 渲染环境必须内置中文字体（如 Noto Sans SC / 思源黑体），字幕不得出现方块或缺字。
- **FR-263** 渲染**不得**对作品做任何重绘、滤镜、美颜或生成式处理；仅允许等比缩放、留边、转场与叠加片头片尾/字幕/音乐。

### J. 成片内容规则

- **FR-264** 片头固定 3 秒：机构 Logo + 对象名（学员名或班级名）+ 周期 + 标题。
- **FR-265** 作品帧：等比缩放至长边 ≤1920，暖白（`#FBF8F2`）留边，单帧停留 3.5 秒（含 0.5 秒转场重叠）。
- **FR-266** 课堂照片穿插：每 4 幅作品后插入 1 张照片，停留 2 秒；无照片时自动跳过且不报错。
- **FR-267** 点评金句字幕：个人取自「美术能力」首句（≤24 字），班级取每位学员一句摘要（≤20 字）；必须逐字来自老师确认后的点评，不得改写。
- **FR-268** 片尾固定 4 秒：老师寄语（≤40 字）+ 机构名 + 分享二维码（复用分享令牌）。
- **FR-269** 转场统一为 0.5 秒交叉淡入，禁止缩放、旋转、粒子等特效。
- **FR-270** 缺课课次在个人视频中以 1.5 秒留白卡呈现，文案 ≤16 字，沿用现有缺课语气。
- **FR-271** 字幕与片头文字必须走与装裱一致的**安全字体白名单**。
- **FR-272** 成片内不得出现原图、推理轨迹、内部提示词或任何联系方式。

### K. 时长与自动精选

- **FR-273** 个人成片目标时长 ≤120 秒；班级成片目标时长 ≤300 秒。
- **FR-274** 超出上限时必须按课次时间线**均匀取样**，且首末两幅必留。
- **FR-275** 班级分配必须先保证每位学员至少 1 幅，再按作品数比例分配剩余配额。
- **FR-276** 提交前必须显示「本周期共 N 幅，已精选 M 幅收录」与预估时长。
- **FR-277** 老师必须可以手动排除指定作品，排除后重新计算时长与收录清单。
- **FR-278** 被时长排除的作品必须完整保留在成长档案中，只是不进入视频。

### L. 编排

- **FR-279** 个人成片按课次日期**升序**串联该学员的作品。
- **FR-280** 班级成片按**学员分段**：每位学员一段，段首 1.5 秒姓名卡（姓名 + 作品数）。
- **FR-281** 班级学员顺序默认按班级名单，生成前可调整；片段内按课次时间线。
- **FR-282** 班级成片必须串成**一条**视频，不得输出多份碎片。

### M. 预览、下载与分享

- **FR-283** 必须提供竖屏 9:16 自适应播放器供老师预览，支持全屏。
- **FR-284** 必须支持下载 MP4，命名规则 `{对象名}_{周期}_成长记录.mp4`。
- **FR-285** 成片必须可挂到家长分享链接中播放，分享页播放器必须带 `playsinline`。
- **FR-286** 成片分享必须遵守与图文分享相同的授权校验、有效期与撤回规则。
- **FR-287** 成片文件地址必须使用带签名的临时 URL，不得暴露永久直链。
- **FR-288** 成片必须记录 `specSnapshot`（帧序、时长、字幕、音乐）以支持复现。

### N. 音乐库与版权

- **FR-289** 管理端必须提供音乐库页面，支持从**授权曲源**搜索（关键词 / 情绪 / 时长 / BPM 过滤）。
- **FR-290** 必须支持试听与下载入库；入库统一转码为 mp3 128kbps 并存储。
- **FR-291** 入库必须去重：来源 URL + 文件 hash 相同者不得重复入库。
- **FR-292** 每首曲目必须记录：标题、作者、时长、BPM、情绪标签、来源 URL、来源平台、授权类型、授权凭证、是否可商用、授权到期日。
- **FR-293** 曲目授权状态为 `pending / confirmed / expired`；新建入库**默认 `pending`**。
- **FR-294** 老师端**只允许**选择 `confirmed` 且未过期的曲目；`pending` 曲目在老师端不可见。
- **FR-295** 成片必须记录所用曲目 id 与授权凭证快照，支持事后举证。
- **FR-296** 搜索框下方必须**常驻**版权提示：「请仅下载可商用授权音乐，并保留授权凭证」。
- **FR-297** 下载失败必须给出可读原因（防盗链 / 超时 / 格式不支持）并支持重试。
- **FR-298** 必须支持静音成片，且**静音为默认值**。
- **FR-299** 音乐必须做 1.5 秒淡入 / 2 秒淡出与音量归一化。
- **FR-300** 授权到期后必须提示「音乐授权已到期，建议更换或静音」并记录处置结果。

### O. 版本、清理、权限与性能

- **FR-301** 成片必须落库，键为 `videoKey`（对象 + 周期 + 类型），含 `version / generatedAt / specSnapshot`。
- **FR-302** 归档作品更新后**不得自动重出**成片，必须提示「有 N 幅作品已更新，建议重新生成」。
- **FR-303** 「重新生成」必须 `version` 自增，并保留历史版本可回看与下载。
- **FR-304** 删除成片只删除成片与中间产物，不影响归档记录；归档记录删除时必须级联删除成片。
- **FR-305** 渲染中间产物与成片的保留期必须可配，到期清理需可预览影响范围。
- **FR-306** 只有本班老师可提交与下载成片；管理员可审计；家长仅可通过有效分享链接播放。
- **FR-307** 提交、完成、下载、分享、更换音乐、删除必须写入审计日志。
- **FR-308** 个人成片（约 60 秒）渲染时间 ≤ 成片时长的 50%；班级成片（约 5 分钟）≤ 3 分钟。
- **FR-309** 任务卡片必须显示进度与预估剩余时间，并支持离开页面后恢复。
- **FR-310** 手机端播放器必须竖屏自适应且支持全屏；下载必须在 iOS Safari 与微信内置浏览器可用或有明确替代指引。
- **FR-311** 弱网下重复提交必须由幂等 `jobKey` 保证不重复创建任务。
- **FR-312** 390px 宽度下任务卡片、播放器与音乐选择面板不得溢出。
- **FR-313** 成片生成必须与阶段报告**解耦**：视频渲染失败不得导致图文报告生成失败。
- **FR-314** 渲染服务不可用时，老师端必须明确显示「视频服务暂不可用」，**不得**显示假成片或假时长。

## 7. Non-Goals（本期不做）

- **不做原图上传与展示**：原始拍摄图永不上传，这是隐私红线，不是待办。
- **不做生成式 AI 视频**：成片必须是既有作品的**确定性蒙太奇**；不得调用 Seedance 等生成式模型去"重画"孩子的作品。
- **不做课堂视频混剪**：本期成片只使用成品作品图与课堂照片；课堂影像依赖已被移除的上传能力与服务端转码，不在本期恢复。
- **不做老师录音 / AI 语音旁白**：本期只有背景音乐与文字字幕，不做配音与 TTS。
- **不做视频模板的可视化编辑器**：帧率、时长、转场、字幕位置由平台预设，老师只做「选周期 / 选题 / 选音乐」三件事。
- **不做短视频平台直传**（抖音 / 视频号一键发布）：只做下载与链接分享。
- **不做音乐库的公开分发**：曲库仅本机构内部使用，不对外开放下载。
- **不做自动定时生成报告与视频**：不排期、不自动推送，必须由老师主动生成。
- **不做家长端在线批注、点赞、留言**：家长端保持只读。
- **不做报告模板的可视化编辑器**：沿用现有报告版式，不做拖拽装修。
- **不做短信 / 公众号 / 企微消息推送**：转发走「复制链接 + 二维码」。
- **不做跨机构档案迁移与合并**。
- **不做归档数据的家长自助导出**（老师端下载成品素材保留）。
- **不做「成长集锦 / 作品集」在第四步的替代入口**：生成类动作统一在成长档案页。

## 8. Design Considerations

### 8.1 第四步的信息层级

- 第四步是**收尾确认页**，不是功能大厅：一句话结论（已写入成长档案）+ 一张卡片式归档摘要 + 两个主按钮。
- 归档摘要卡片必须能回答：**谁、哪节课、哪幅作品、什么时候归档、第几版、图同步好了没**。
- 转发状态用一个小徽标呈现（未转发 / 已转发 / 已撤回），点击展开详情，不占用主视觉。
- 熊猫伙伴在此页承担情绪收尾（沿用现有的 `pandaObserve`），不承载操作。

### 8.2 成长档案的"常驻感"

- 进入即是**时间线**，纵向按日期排列，缺课记录用现有的温柔留白卡片样式。
- 周期与对象放在顶部作为**筛选条**，不要做成表单式"选择 + 生成"的流程感。
- 阶段报告是时间线之上的一个**入口卡片**：未生成时显示「为本学期生成一份阶段报告」，已生成时显示报告封面 + 生成时间 + 「查看 / 更新」。
- 视觉沿用品牌暖金 / 墨黑 / 暖白，高级感来自留白与秩序，不靠装饰堆砌。

### 8.3 移动端

- 第四步与转发弹窗在手机上以底部抽屉呈现，主按钮固定在拇指区。
- 二维码在手机上要能直接长按保存或「保存到相册」。
- 档案时间线单列，图片采用固定宽高比占位，避免滚动时跳版。

### 8.4 复用现有组件

- 缺课记录复用 `GrowthArchiveData.jsx` 的 `GentleAbsence`。
- 报告版式复用 `LessonHistory`、`Radar`、`StageGrowthReview` 的结构，但**数据必须改为从归档聚合并替换掉写死文案**。
- 二维码渲染复用装裱水印中已有的二维码能力（见 `tasks/prd-smart-framing-v2.md`）。
- 归档记录读写复用 `feedbackRecordsApi.js` 的 `record_key` 幂等 upsert 与孤儿行清理逻辑。

### 8.5 成长记录（视频）的体验

- 视频是**一次成片**，不是编辑器：老师只做三件事——**选周期、选题、选音乐**，其余参数由平台预设。
- 时长必须对家长友好：个人 ≤2 分钟、班级 ≤5 分钟；被精选掉的作品要在界面上说清楚，不能让老师误以为"画丢了"。
- 作品帧必须是**安静、满幅**的：暖白留边、不加速、不堆动效——孩子的画是主角，转场只负责换气。
- 片尾二维码是转化入口：家长看完直接扫码看完整档案。
- 任务卡片要像一张**快递单**：排队中 / 渲染中（进度 + 剩余）/ 已完成（时长 + 体积）/ 失败（原因 + 重试），一眼就知道走到哪一步。
- 音乐选择面板**默认静音**，并且把版权提示放在选择**之前**而不是之后。

### 9.2 关键技术决策

1. **先有课次实体，才有可靠去重**：当前原型的「创建信息」一步没有真正的课次表，`lessonId` 无处可取。第一期用 `className + date + studentId + title` 作为退化唯一键，并在 PRD 中把"建立课次实体"标为依赖（见开放问题 Q1）。
2. **归档是 upsert 而不是 append**：`archiveRecord` 的 `if(!archived)` 是"防止重复"的补丁，正确做法是业务唯一键 + upsert。这样"改完再归档"天然可用。
3. **原图绝不入库**：`feedbackRecordsApi.js` 现有的 `httpOnly()` 过滤是在"防止失效地址入库"，本次要把语义升级为**硬规则**——原图字段根本不存在于归档 payload 中，从模型层面杜绝。
4. **素材上传与归档解耦**：先落归档（元数据 + 点评），素材异步上传并回填。这样弱网、存储故障都不会让老师的收尾动作失败。
5. **档案与报告分离**：档案是**查询视图**（实时来自归档记录），报告是**快照实体**（生成后落库）。这直接回答「为什么每次都要生成」——因为过去把两者混成了一个页面。
6. **分享令牌与授权联动**：`shareToken` 是访问凭据，授权是业务前提。撤回授权时必须级联失效已发出的链接，避免"家长已撤回授权但链接仍能打开"。
7. **收敛死代码**：`TeacherFlow`、旧 `GrowthArchive` 删除后再动档案逻辑，否则每改一次要改两处，回归风险翻倍。

### 9.6 服务端 ffmpeg 渲染管线（Q1 = B）

**渲染步骤**

1. **素材归一化**：成品图等比缩放到长边 ≤1920，暖白 `#FBF8F2` 补边，输出 PNG（避免二次 JPEG 损失）。
2. **单帧片段**：每幅作品渲染为 3.5 秒静止片段（含 0.5 秒转场重叠时长）。
3. **字幕叠加**：`drawtext` 绘制点评金句；字体走安全白名单；颜色与品牌一致。
4. **拼接**：`concat` demuxer 或 `xfade` 滤镜链，转场统一 0.5 秒。
5. **片头 / 片尾**：由模板生成（Logo + 文字 + 二维码）。
6. **混音**：音乐 1.5 秒淡入 / 2 秒淡出并做音量归一化；静音时输出无音轨或静音轨。
7. **编码**：`libx264 -profile:v high -pix_fmt yuv420p -movflags +faststart`；音频 AAC 128kbps。
8. **上传**：写入对象存储，返回 `storageKey` 与带签名的临时 URL。

**必须提前规避的坑（逐条写进实现清单）**

- 渲染容器**必须安装中文字体**，否则全部字幕变成方块——这是最容易在上线后才发现的坑。
- `drawtext` 中的 `:`、`'`、`%`、`\` 必须转义，否则整个滤镜链解析失败。
- 素材尺寸不一致必须先 `scale + pad` 统一，否则 `concat` 失败或比例错乱。
- 30fps 下 `xfade` 要求两段都长于转场时长，单帧片段过短会直接报错。
- 竖屏必须显式 `scale=1080:1920:force_original_aspect_ratio=decrease,pad=1080:1920:(ow-iw)/2:(oh-ih)/2`。
- 微信内置浏览器要求 `yuv420p` + `faststart`，否则黑屏或不播。

### 9.7 视频任务与队列

- 任务表 `video_jobs`（字段见 FR-257），状态机与进度见 FR-256。
- 渲染进程与 Web 服务**分离部署**，避免长任务阻塞接口；单机构并发默认 2。
- **断点续渲**：以「帧片段」为单位持久化中间产物，重试只重渲失败段。
- **硬超时**：个人 5 分钟 / 班级 15 分钟，超时判失败并可重试。
- **解耦**：视频渲染失败不得影响阶段报告（图文）的生成与查看（FR-313）。

### 9.8 音乐库

**建议新增云表 `music_tracks`**

| 字段 | 说明 |
|---|---|
| `track_key` | 幂等键 |
| `title / artist / duration / bpm / mood` | 元数据 |
| `source_url / source_provider` | 来源与曲源平台 |
| `license_type / license_proof_url / license_status / license_expires_at` | 授权信息（`pending / confirmed / expired`） |
| `file_key / file_url / hash` | 入库文件与去重 hash |
| `created_by / created_at` | 操作留痕 |

- **搜索**：服务端代理调用授权曲源 API（密钥不下发前端），支持关键词 / 情绪 / 时长 / BPM 过滤。
- **下载入库**：服务端抓取 → 探测格式 → ffmpeg 转 mp3 128kbps → 存储 → 记录 hash 去重。
- **合规闸门（必须）**：新建入库默认 `license_status='pending'`；老师端只读 `confirmed` 且未过期的曲目；成片记录授权凭证快照。
  > 理由：把音乐混进视频发给家长属于**商业使用**场景。来源不清、无授权凭证的音乐一旦使用，侵权责任由平台承担。因此本模块的默认状态必须是"不可用"，由管理员确认授权后才放开。

### 9.9 当前工程依赖与风险（重要）

- **现有工程无法端到端实现本模块**：云 SDK 只有 chat / models / database / storage 四个模块（无视频端点）；`prototype/server/index.mjs` 是本机内存适配器，且显式禁用视频大文件上传（503）。
- 因此落地顺序必须是：① **服务端渲染服务**（独立部署、带 ffmpeg 与中文字体）→ ② **对象存储与服务端上传** → ③ 前端接口对接 → ④ 真机验收。
- 在 ① ② 就绪前，前端只能按接口契约开发并用 mock 数据，**所有 mock 必须在界面上明确标注**（例如「演示数据 · 视频服务未接入」），不得出现写死的时长与假播放器。
- 本模块**不依赖生成式视频模型**，因此不占用现有「视频生成模型池」的额度，也不受其价格与稳定性影响。
- 成本提示：一条 5 分钟 1080p 成片约 20–40MB（含 BGM 与字幕），存储与流量成本需纳入配额（见开放问题 Q12）。

- **Q3** 分享链接默认 30 天有效期是否合适？是否允许老师选择「永久有效（可随时撤回）」？
- **Q4** 「成长记录（视频）」本期只做结构占位，成片依赖视频服务。是否接受先给"待生成"状态，还是直接从报告类型里隐藏？
- **Q5** 报告是否需要**长图 / PDF 导出**（家长转发常用长图）？这与 `tasks/prd-smart-framing-v2.md` 的开放问题 Q1（PDF 打印稿）是同一件事，建议合并决策。
- **Q6** 归档后老师又在第二步**重新装裱**了作品，档案里的图片要不要跟着更新？本 PRD 默认"重新归档即更新"，需要确认是否要保留旧版图片（版本化素材）。
- **Q7** 班级成长档案要输出**一份班级报告**，还是**每位孩子各一份**？本 PRD 默认为班级聚合报告 + 可下钻到个人。
- **Q8** 家长撤回授权后，已打开过的页面（浏览器已缓存）如何处理？本 PRD 默认"下次打开即失效"，不做强制清除已缓存内容。
- **Q9** 归档数据保留期与主 PRD §8.3 的默认容量规则如何对齐？是否需要按机构单独配置。
- **Q10（阻塞音乐库）** 授权曲源选哪一家？（Epidemic Sound / Artlist / 爱给网商用授权 / 自建曲库）这决定搜索接口、授权凭证形态与计费方式。**在选定之前，音乐库的"搜索 + 下载"不应上线。**
- **Q11（法务风险）** 你要的「搜索网上音乐并下载到音库」，如果指向**未授权曲源**，把音乐混进视频发给家长属于商业使用，侵权责任由平台承担。是否接受「**只从已签约的授权曲源检索**」这一限制？还是需要保留「管理员人工上传 + 人工确认授权」的兜底通道？
- **Q12** 成片的**存储与流量成本**：一条 5 分钟 1080p 成片约 20–40MB。保留期、按机构配额、以及"成片超过 N 个月自动降码率/清理"是否需要？
- **Q13** 是否需要**横屏版本**（电脑 / 教室投影观看）？本 PRD 默认只出竖屏 9:16。
- **Q14（阻塞开工）** 当前原型环境没有服务端视频能力（云 SDK 无视频端点、本机适配器显式禁用大文件上传）。是否接受「前端先按接口契约 + mock 交付，服务端渲染单独排期」？若不接受，本模块必须等服务端就绪后才能开工。
- **Q15** 班级集锦的学员顺序：按**班级名单固定顺序**，还是按**本期作品数/活跃度**排序？本 PRD 默认按名单顺序且生成前可调整。
- **Q16** 成片里的**点评金句**是否会出现"孩子被公开对比"的风险？班级集锦中每位学员的字幕长度是否应统一上限（本 PRD 默认 ≤20 字），避免某位孩子明显被写得更少？
